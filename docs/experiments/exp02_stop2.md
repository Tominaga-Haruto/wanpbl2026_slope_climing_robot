## 1. P3a 姿勢保持の診断（stiffness 3条件）

Hydra ではなく `stance_check.py` に `--stiffness_scale` を足して cfg を直接書き換えた

0.5 s 時点の「目標角 − 実測」（左右平均 [rad]）:

| stiffness | HR | HAA | HFE | KFE | FFE |
|---|---|---|---|---|---|
| x1 | -0.0051 | -0.0001 | -0.0142 | **-0.0465** | **+0.1604** |
| x2 | -0.0051 | +0.0007 | +0.0064 | +0.0140 | **+0.1648** |
| x4 | -0.0048 | +0.0006 | +0.0056 | +0.0143 | **+0.1094** |

**「PD 剛性不足で関節が沈む」という仮説は否定された。**

- 剛性 4 倍でも転倒率 64/64、向きも前（pitch > 0 かつ x 変位 +）のままで、変位はむしろ **増える**。
- 膝の沈みは x1 で −0.0465 rad（2.7°）しかなく、x2 で符号が反転する。
  必要トルクは 0.0465 × 15 ≒ 0.7 N·m で、見積もりの「数 N·m で 0.2〜0.5 rad」には全く当たらない。
- 唯一大きいのは足首 FFE の +0.16 rad（9.2°）だが、**剛性 4 倍でも 1.5 倍しか縮まない**
  （0.160 → 0.109）。純粋な PD コンプライアンスなら 1/4 になるはずなので、これは「沈み」ではなく
  **倒れ込みで増え続ける重力モーメントに足首が抗っている**状態。必要トルクは x1 で約 1.6 N·m、
  x4 で約 4.4 N·m と増えており（effort_limit 20 N·m には遠い）、飽和でもない。
- 結論: 公称姿勢は**動的に前へ倒れていく姿勢**であって、関節の沈みの問題ではない。
  支持多角形の中に COM があるのに倒れるので、足裏が全面接地していないか、接地時の沈み込み
  （base 高さ 0.3758 → 0.3613 m、1.45 cm 落ちる）で姿勢が変わっているあたりが次の疑い先。今回は追っていない。

### 3-3. ただし F は円を描いて歩く

S1 の yaw rate が +0.324 rad/s。10 s で 3.2 rad ≒ 186° 回る計算になり、進行方向角 +94.3°／+105.3° は
「真っ直ぐ進んでいない」というより **円軌道を描いている**ことを示す。
S2 の heading ずれ −102.9° も同じことを別の量で見ている。
これは +401 → +1001 → +1499 で単調に悪化している（S1 yaw rate 0.103 → 0.162 → 0.324）。

一方で S6（旋回指令 0.5）に対する応答は +1001 で +0.143 と全ラン中の最高値を出したのに、
+1499 では +0.010 に戻っている。**「指令と無関係に勝手に回る」方向に進んでいて、
「指令どおり回る」方向には進んでいない。**

参考指標: 遊脚の最大高さは F @+1499 で S1 11.2/13.3 cm、S2 13.5/16.5 cm と B（11.0/10.5、12.7/12.9）より
高い。rough で足を高く上げるようになったぶんが平地にも出ている。着地回数は 7〜8 回/s で B と同程度。

## 4. 所見

1. **P3a: 剛性不足ではなかった。** stiffness 4 倍でも 64/64 が前に倒れ、変位は逆に増える。膝の沈みは 2.7°
   しかない。公称姿勢が動的に前倒れであること自体が原因で、PD ゲインの問題ではない。
2. **F: 平地 → rough の移行は成功。** terrain_levels が 0.98 → 4.69 まで上がり（A は 3000 iter で 0 のまま）、
   正規化 err_xy 0.21〜0.26 を保ったまま。平地の歩行も忘れていない。坂に向けた道筋としては有望。
3. **ただし F は円を描く。** S1 yaw rate が +0.103 → +0.162 → +0.324 と単調に悪化し、S2 の heading は
   10 s で −103°。旋回「指令への追従」は E の `rel_heading_envs=0.5` でも +0.063 止まりで、
   yaw は指令・非指令の両方向で未解決のまま。

## 5. 次の候補

1. **yaw の報酬関数を G1/H1 と同じものに替える。** いまは `track_ang_vel_z_exp`（base フレームの
   `root_ang_vel_b[:,2]`）と `track_lin_vel_xy_exp`（roll/pitch 込みの base フレーム）を使っている。
   同梱の `track_ang_vel_z_world_exp`（`root_ang_vel_w[:,2]`）と `track_lin_vel_xy_yaw_frame_exp`
   （yaw のみのフレーム）は引数の並びが同じで `func` の差し替えだけで済む（P1-3 で確認済み）。
   F の「勝手に回る」も E の「指令で回らない」も、yaw をどのフレームで測るかの問題である可能性がある。
   平地の B 相当 ＋ 関数差し替えの 1 本で確かめられる。
2. **F をそのまま延長する。** terrain_levels はまだ 4.69 で上昇中、time_out も 0.50 まで来ている。
   あと 1500〜3000 iter で頭打ちになるかを見れば、「rough を最後まで登れるか」が分かる。
   円を描く問題は候補 1 と直交するので、両方同時に走らせられる。
