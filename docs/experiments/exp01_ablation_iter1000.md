## 読み取れること

1. **どちらの単独変更でも B は再現しない。** 報酬＋std だけ（C_noflat）は A と区別がつかないほど
   完全に立ち往生する。平地だけ（C_flatonly）も前進指令では立ち往生する。
   B が歩けたのは **平地 と 報酬/std の組み合わせ**が要る、というのが今回の答え。

2. **平地だけでも「後退」は獲得する**（C_flatonly の S4 で v_x -0.274、静止率 0 %）。
   前進（S1・S2）は固まったまま。前進と後退で獲得の難易度が違うという、今まで見えていなかった
   非対称性が出た。原因は未調査。

3. **rough 地形は terrain_levels が一度も上がらない。** A も C_noflat も iter 1000 時点で
   `Curriculum/terrain_levels` が 0 のまま（A は 3000 iter でも 0）。`terrain_levels_vel` は
   「指令距離の半分以上進めたら昇格」なので、**歩けない → 昇格しない → 難しい地形のまま →
   歩けない** のループに入っている。`max_init_terrain_level=0` との組み合わせが効いている疑いが濃い。

4. **旋回だけは C_noflat が一番良い**（S6 で +0.175、error_vel_yaw 0.202 は 4本中最良）。
   rough 地形のほうが yaw を使う動機が強いのかもしれない。B の弱点（S6 で +0.028）と逆向きなので、
   最終的には両立させたい。

## 次に試すなら

1. **rough 地形のまま `max_init_terrain_level` を上げる**（例: `None` にして初期レベルを
   ばらけさせる）。今回の結果だと、地形カリキュラムが 0 から動かないことが立ち往生の
   直接の入口に見える。地形を平地に逃がさずに済むなら、そのほうが最終目的（坂登坂）に近い。
2. **前進だけ獲得できない非対称性を潰す。** C_flatonly が後退はできて前進はできない理由を、
   指令レンジ（`lin_vel_x=(-1.0, 1.0)`）と初期姿勢（HFE/KFE/FFE の符号）の関係から見る。
   併せて `track_lin_vel_xy_exp` を G1/H1 と同じ `track_lin_vel_xy_yaw_frame_exp` に替える案も
   ここで一緒に試せる。

C_noflat / C_flatonly はどちらも max_iterations 3000 でまだ走っている。止めるか続けるかは判断待ち。
