## 4. 所見（3行以内）

1. base の前後を直しても 08-21 設定のままでは立ち往生は消えない。A は iter 500→1600 で
   error_vel_xy が 0.264→0.838 と悪化し、feet_air_time 報酬が一貫して負（足が threshold 0.2 s まで
   上がらない）、base_contact 0.93→0.51／time_out 0.06→0.49 と、**追従を捨てて転ばないことだけを
   覚える局所解**に入っている。評価でも全シナリオで完全静止（静止率 100 %、10 s 間に接地イベントゼロ）。
2. B の複合対策では立ち往生・カニ歩きとも消えた。S1 で v_x 0.429、S2 で 0.928 と指令を追従し、
   横ずれ v_y は ±0.013、進行方向角は ±4° 以内。S5 の横移動指令にも v_y +0.294 で応じている。
3. ただし B は S5（横移動）の転倒率が 46.9 %、S4・S5 で heading が 10 s に 38〜54° 流れており、
   横方向と旋回の扱いは未解決。前後方向だけが仕上がっている状態。

## 5. 次の候補（1〜2個）

1. **B の3系統のうちどれが効いたかの切り分け**（B から1つずつ戻す3本: 平地だけ / dense 足上げだけ /
   std 0.35 だけ）。A と B の差が大きすぎて、今のままでは「平地にしたから歩けた」だけの可能性を
   否定できない。特に A は rough 地形で `max_init_terrain_level=0` かつ terrain_levels カリキュラムが
   一度も上がっていない（500/1000/1600 すべて 0）ので、地形が難しすぎて立ち往生に落ちた線が濃い。
2. **横方向・旋回の追従を別に手当て**する。B の S5 転倒率 46.9 % と S4/S5 の heading 流れは、
   `track_lin_vel_xy_exp` が root の **COM 速度をフル姿勢（roll/pitch 込み）の base フレーム** で
   測っていることと無関係ではないかもしれない。G1/H1 が使う `track_lin_vel_xy_yaw_frame_exp`
   （yaw のみのフレーム）に替えるのが最小の一手。

## 付録: 今回の運用で変えた点（指示書との差分）

1. **`terrain_type=plane` が使えなかった。** `TerrainImporter.import_ground_plane` は
   `GroundPlaneCfg` のデフォルト usd_path（S3 の `Isaac/5.1/Isaac/Environments/Grid/default_environment.usd`）を
   必ず引きに行き、`FileNotFoundError: Unable to open the usd file` で落ちる（URL 自体は HTTP 200 で
   到達可能なので Omniverse 側の resolver の問題）。このパスは importer 内にハードコードされていて
   cfg から差し替えられない。
   → `terrain_type=generator` のまま `sub_terrains` の proportion を flat=1.0 / 他すべて 0.0 に
   上書きして「全面平地」を作った。ローカル生成・ネット不要で、物理的には平面と同じ。
   ラン B と measure_crab.py の両方で同じ方式を使用。

2. **自作 `feet_air_time_positive_biped` の引数が Isaac Lab 同梱版と違う**（`threshold` ではなく
   `threshold_min` / `threshold_max`）。自作側を使い、`threshold_min=0.0, threshold_max=0.4` とした。
   reward は常に非負なので `reward *= reward > 0.0` は何も削らず、同梱版 `threshold=0.4` と数値的に等価。
   weight は G1 と同じ 0.25。

3. **weight 0.0 の報酬項は RewardManager が加算処理ごとスキップする**（`reward_manager.py:145-148`、
   関数自体が呼ばれない）。よって `feet_air_time_biped` を weight=0.0 で足したラン A の挙動は完全に不変。

4. **トルク飽和率は actuator 側の effort_limit から計算した。** `robot.data.joint_effort_limits`（sim 側）は
   1e9 で、DelayedPDActuator は explicit actuator なのでクリップは actuator 内で行われる。
   実際に使った上限は HR 24 / HAA 30 / HFE,KFE 30 / FFE 20 N·m。

5. **Isaac Lab の実体は `D:\Tominaga\IsaacLab`**（editable install の参照先、train.py の
   skyentific import パッチ入り）。`D:\IsaacLab` も存在するが別物なので読まない。

6. **`play.py --video` は未確認**。優先度を下げて後回しにした（学習2本が GPU を占有している間に
   描画を伴う起動を試すのは避けた）。
