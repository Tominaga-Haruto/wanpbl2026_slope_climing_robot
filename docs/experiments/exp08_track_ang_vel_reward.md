# 実験08: track_ang_vel_z_exp の std/weight 調整による初のその場旋回合格チェックポイント

2026-09-17夜〜18日未明。実験07の診断(その場旋回時にHRトルクが実効上限の2〜4%しか
使われていない)を受け、`track_ang_vel_z_exp`のstd/weightのみを変更して追試。
詳細な全数値は`tools/logs/REPORT_exp08_stop8b.md`(git管理外)。

## L0: 事前計算

- **歩くと1stepあたり増える罰(K2データより)**: H_eff13p5@2999で-0.143、J_turn_scratch@1000で-0.167、
  @2999で-0.164。
- **track_ang_vel_z_expの計算**(`isaaclab/envs/mdp/rewards.py:318-326`、`exp(-error^2/std^2)*weight`):
  cmd_wz=0.5(S6/S9相当)で、現行(std0.5,w0.5)は静止時reward 0.184→完全追従時0.500(差+0.316)。
  std0.35,w0.5では+0.435、std0.35,w1.0では+0.870まで拡大。理論上の誘因は歩行の罰(0.14〜0.17)を
  現行設定でも上回っているが、実測のyaw rateは0.01〜0.07にとどまっていた(=報酬設計だけの
  問題ではない可能性)。

## L本番: 2ラン(H_eff13p5@2999から+1500iter resume、4096env、seed1)

1. `L_angstd`: `track_ang_vel_z_exp.params.std=0.35`(weight据え置き0.5)
2. `L_angstd_w1`: 同上 + `track_ang_vel_z_exp.weight=1.0`

起動前に64env/20iterのスモークテストでJ_turn_resumeの`params/env.yaml`と丸ごとdiffし、
差が意図した変更のみであることを確認(1回目は地形flat化の比率上書き漏れを発見・修正)。

## 結果

**`L_angstd_w1`の+1000(`model_4000.pt`)で、実験06の判定基準をプロジェクトで初めて満たした**:
S6 yaw=+0.268、S9 yaw=-0.353、符号一致、比率0.76(∈[0.5,2])、\|(vx,vy)\|平均0.013、転倒率0、
両足着地。既存基準(S1速度・カニ歩き・転倒率)への退行なし。

`L_angstd`(weight据え置き)は+500/+1000/+1499の3チェックポイントとも不合格。効いたのは
主にweight=1.0への変更で、std短縮単独では不十分だった。

**ただし、同じrunの+1499(最終、`model_4498.pt`)では再び判定基準を外れた**
(S6=+0.122未達、比率0.29で範囲外)。S6は学習が進むにつれ低下(+0.319→+0.268→+0.122)、
S9は逆に強くなる(-0.112→-0.353→-0.422)傾向で、+1000付近はその交差点にあたる。
1点だけの合格は再現性・安定性が未確認であり、この時点ではデプロイ候補にしなかった
(→実験09で密な評価により検証)。
