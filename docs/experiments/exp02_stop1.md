## 3. P1-1 レベル 0 の地形実寸（詳細は `P1_terrain_level0.md`）

難易度は `difficulty = (sub_row + U(0,1)) / num_rows`、`difficulty_range=(0,1)` なので
**行 0（レベル 0）は difficulty ∈ [0.0, 0.1)**。列は proportion の累積で決まり 20 列に固定配分される。

| sub_terrain | proportion | 列数/20 | レベル 0 での実寸 |
|---|---|---|---|
| flat | 0.30 | 6 | 完全な平面 0 cm |
| hf_pyramid_slope | 0.10 | 2 | 勾配 0〜4 %（0〜2.3°）、頂点 0〜16 cm |
| hf_pyramid_slope_inv | 0.10 | 2 | 同じ深さのすり鉢 0〜16 cm |
| pyramid_stairs | 0.05 | 1 | 段差 0〜1.0 cm、踏面 30 cm |
| pyramid_stairs_inv | 0.05 | 1 | 段差 0〜1.0 cm |
| wave_terrain | 0.20 | 4 | 全振幅 0〜2.0 cm、波長 2 m |
| **random_rough** | 0.20 | 4 | **difficulty 無視。常に 10 cm 角セルごとに {0, 2, 4, 6} cm を一様抽選** |

`size=(8,8)`, `num_rows=10`, `num_cols=20`, `horizontal_scale=0.1`, `vertical_scale=0.005`。

**レベル 0 でも env の 20 % は 6 cm までのランダム凹凸の上にいる**（脚の付け根高さ 0.376 m の約 16 %）。
`random_uniform_terrain` は difficulty を使わないので、カリキュラムを下げてもこのタイルだけは常に最大荒さ。
rough で前進が獲得できない原因の第一候補はこれ。

## 4. P1-2 前進・後退の非対称の手がかり（`stance_check.md`）

64 env、平地、評価と同じ中立設定、公称姿勢（joint scale 1.0）。

### 初期姿勢の COM と支持多角形

| 量 | 値 |
|---|---|
| 全身 COM（base 座標） | x **-0.0941**, y -0.0184, z -0.0355 m（全質量 10.106 kg） |
| base 高さ（接地面から） | +0.3613 m |
| lr_ffe 足裏の x 範囲 | -0.2093 .. -0.0377 m |
| ll_ffe 足裏の x 範囲 | -0.1984 .. -0.0280 m |
| **支持多角形の x 範囲** | **-0.2093 .. -0.0280 m**（幅 0.181 m） |
| 支持多角形の中心 x | -0.1187 m |
| COM から前縁（+x）までの余裕 | +0.0660 m |
| COM から後縁（−x）までの余裕 | +0.1153 m |

求め方: 足リンク配下の衝突メッシュ頂点（instance proxy を辿って取得、lr 10194 頂点 / ll 10158 頂点）を
リンク座標で集め、シミュレータのリンク姿勢で base 座標に変換。「足裏」は各足の最下点から 1 cm 以内の頂点のみ。

**COM は支持多角形の中心より 2.5 cm 前寄り**（前余裕 6.6 cm に対し後余裕 11.5 cm）。静的には内側だが前に偏っている。

### action=0（＝公称姿勢を保持）で放置したとき

| 量 | 値 |
|---|---|
| 5 s 時点の転倒率 | **1.000（64/64）** |
| うち転倒時 pitch > 0 | **64** |
| うち転倒時 pitch < 0 | 0 |
| 転倒時 pitch 平均 | **+73.07°** |
| 5 s 時点の base x 変位（平均） | **+0.2887 m** |
| 10 s 生存 | 0/64 |

**公称姿勢は静的に安定ではなく、64 env すべてが +x 方向（前）へ 29 cm 動きながら倒れる。**
pitch の符号と x 変位の符号が一致しているので、方向の読み違いではない。

注意: 転倒した env は `step()` の中で自動リセットされるため、記録はすべて「終了する直前のステップの値」を
使っている（最初の実装ではリセット後の姿勢を読んでいて pitch がほぼ 0 になっていた。修正済み）。

### 解釈（仮説、断定しない）

公称姿勢がそもそも前倒れなので、方策がまず覚えるのは「前に倒れないよう後ろへ押し返すこと」になる。
その副産物として後退方向の速度はただで手に入り、前進は「自分から不安定側へ踏み出す」必要があるため後回しになる。
C_flatonly が後退（1000）→ 前進（2400）の順で獲得したこと、C_noflat が 2999 で後退だけ獲得したことは、
この順序と整合する。ただしこれは 1 本の初期姿勢テストからの推測で、検証はしていない。

- **遊脚中の足の最大高さ [cm]**: 接触センサの `current_air_time > 0` の間、足リンク原点の高さ
  （`body_link_pos_w[:, foot, 2] − env_origins[:, 2]`、平地なので接地面 = env 原点の z）の走行最大値を保持し、
  接地の瞬間（`compute_first_contact`）にその値を1回ぶんとして計上、以後リセット。全接地回の平均。

## 8. 所見

1. 立ち往生の原因は地形。**平地にするだけで（iter 2400 までに）解消し、報酬・std の変更は不要**だった。
   実験01 で書いた「組み合わせが要る」は iter 1000 だけを見た誤りで、撤回する。
2. rough が効かないのは、レベル 0 でも 20 % のタイルが **6 cm のランダム凹凸**（difficulty 無視）で、
   歩行時の遊脚高さ 9〜13 cm と同オーダーだから、という説明が今のところ最も素直。
3. 旋回は 4 本とも未獲得（S6 で 0.02〜0.04 rad/s）。原因は `rel_heading_envs=1.0` により
   学習中に旋回速度指令そのものを経験していないこと。E_yawcmd で直接検証できる。
