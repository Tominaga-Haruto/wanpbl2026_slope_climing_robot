## 分かったこと

### 立ち往生

**原因は地形。平地にするだけで解消する。報酬・std の変更は不要。**

実験01 の時点では「平地と報酬/std の組み合わせが要る」と結論したが、これは iter 1000 だけを見た誤りで、
実験02 で撤回した。C_flatonly（平地だけ変更）は iter 2400 で完全に歩き出す。
報酬・std は歩き出す時期を早めるだけ（B は 1000、C_flatonly は 2400）。

rough で歩けない理由の第一候補は、レベル 0 でも env の 20 % が **6 cm のランダム凹凸**の上にいること。
`random_uniform_terrain` は difficulty を無視するので、カリキュラムを下げてもこのタイルは常に最大荒さ。
歩行時の遊脚高さ 9〜13 cm と同オーダー。

### 平地 → rough の移行

**成功した。** B@2999 から resume して rough に戻すと、terrain_levels が 0.98 → 4.69 まで上がった
（A は 3000 iter 通して 0 のまま）。平地の歩行も忘れていない。坂に向けた道筋としては有望。

### 旋回

**学習中、旋回速度指令が一度も出ていなかった。** `rel_heading_envs=1.0`（親の既定）なので全 env が
heading 追従になり、サンプルした `ang_vel_z` は `_update_command` で毎ステップ捨てられる。
ただし `rel_heading_envs=0.5` にしても S6 は +0.063 止まりで解決しなかった。
逆に F_BtoRough は指令と無関係に勝手に回る（前進指令で yaw rate +0.324）。

### 初期姿勢

公称姿勢は静的に安定ではなく、action=0 で 64/64 が前へ 29 cm 動きながら倒れる。
**stiffness を 4 倍にしても変わらない**（変位はむしろ増える）ので、PD 剛性不足ではない。

## ユーザーから受けた訂正（重要）

1. **`error_vel_xy` / `error_vel_yaw` は生値で比べてはいけない。** エピソード長に比例する。
   正規化 = 生値 × 500 / `Train/mean_episode_length`。
   これを適用すると A の iter 500 は 0.614 で、「500→1000 で局所解に落ちた」という読みは誤りだった
   （最初から歩いていない）。
2. **`max_init_terrain_level` を上げると初期地形は難しくなる。** レベル 0 が最易。
   「上げる」案は立ち往生を増やす方向なので採らない。
3. **iter 1000 の切り分け結論は早すぎた。** 「1000 で出ない」は「出ない」ではない。

いずれも実物を grep して確認した（`docs/reference/isaaclab_internals.md`）。

## 途中でつまずいたこと

- `terrain_type="plane"` が使えない（ground plane USD がリモート取得できず落ちる）。
  → 全面 flat の generator で代用した。
- headless 起動に `OMNI_KIT_ACCEPT_EULA=YES` が必要。無いと EULA プロンプトで死ぬ。
- `measure_crab.py` の env.reset() が inference_mode の外だとエラーになる。
- 転倒した env は `step()` の中で自動リセットされるので、転倒時の姿勢は「1 ステップ前の値」を使う必要がある。
  最初これを間違えて pitch がほぼ 0 になっていた。
- `stance_check.py` の足メッシュ取得で、USD が instanceable なため `Usd.PrimRange` が素通りしていた。
  `Usd.TraverseInstanceProxies()` が必要。
- `play.py` の `--checkpoint` はファイルパス、`train.py` の `--checkpoint` は名前。挙動が違う。
