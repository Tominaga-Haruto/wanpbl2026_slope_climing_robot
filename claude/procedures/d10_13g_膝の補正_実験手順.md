# D10-13G: 膝の補正（`--knee-trim-deg`）。まず空中で足裏を見て、合っていれば床・方策へ

> 作成 2026-09-24。送信器 build **`D10_13G_KNEETRIM_20260924`**（`.bak_20260924_kneetrim`、テスト 188本 OK）。D10-13F（`d10_13f_最後の1回_左HAA点検とゲイン07_実験手順.md`）の代わりに行う。うまくいかなければ D10-13F に戻る。
> 支え方・禁止事項は D10-13E と同じ。異常があれば主電源を切る。吊り紐は外さない。

## なぜ

- 足に体重が乗った保持では毎回、関節角（HFE+KFE+FFE）が「足裏はつま先上げ 11〜22°」と言うのに、T265 は胴がほぼ直立だと言う。荷重がないときは 3°以内で合う。
  - 中央値は左 −19°、右 −16°（D10-13D/E の保持 13 run）。`--analyze` の新しい行 `SAGITTAL CHECK` で毎回出る。
- 本人所見: 保持姿勢で膝が曲がりすぎて見える。
- **仮説:** 実物の膝は、エンコーダーの値より 16〜19°多く曲がっている。そうなら方策は毎回、自分の姿勢を 16〜19°取り違えたまま始まっている。
- **`--knee-trim-deg 19 16`:** 膝の読み替え（`cad_fk` の KFE の補正）に左 19°・右 16°を足す。保持姿勢で膝は左 19°・右 16°まっすぐになり、方策に渡る膝の角度も同じだけ直る。ほかの関節は変えない。
- **反対の可能性:** ずれは荷重に比例して大きくなる（FFE 2.6 A で −12°、5 A で −20°）。これは、体重が乗ると足裏が床から浮く（かかとかつま先だけで立つ）場合にも起きる。**それを見分けるのが G0 の空中の確認。**

## 0. 電源を入れる前

D10-13F の「0.」と同じ: 左 HAA（0x11）のねじの締め直し、左右のガタの比較、`oa` のとき HAA を水準器で水平に合わせる。**`oa` では、膝をまっすぐ・足裏を胴と平行に、できるだけ正確に合わせる**（この実験の前提）。

実行フォルダはすべて `C:\Users\harut\Connect2USB2CAN`。

## G0: 空中で足裏を見る → 良ければ床に立たせる（方策なし、30 s・要承認）

```powershell
cd C:\Users\harut\Connect2USB2CAN; .venv310\Scripts\python.exe ver9_d8_sender.py --arm --all-axes --floor-limits --stand-only --stand-seconds 30 --zero-offset cad_fk --knee-trim-deg 19 16 --fine-timer --package C:\Users\harut\wanpbl2026_slope_climing_robot\H_eff13p5_2999\H_eff13p5_2999 --ramp-seconds 10 --csv logs\d10_13g_g0_trim_stand.csv --vx 0 --vy 0 --wz 0
```

1. 起動直後に `KNEE TRIM: LL_KFE/LR_KFE offset now +6.7/+8.8 deg` が出ることを確認する。
2. **ramp が終わって保持に入ったら、まだ空中のまま、スマホの傾斜計を胴の上面と足裏に当てて角度を読む**（左右とも）。膝の見た目もメモする。
   - **A. 足裏と胴がほぼ平行（差 5°以内）で、膝の曲がりが自然:** 仮説が合っている。降ろして床に立たせる（保持 30 s）。
   - **B. 足裏がつま先上げに 10°以上傾いている:** 仮説は外れ（ずれは膝の読み違いではなく、荷重で足裏が浮いている側）。**床に降ろさず**、30 s 終わるのを待つ。そのあとは D10-13F に戻る。
3. A で床に立ったら、終わったあと `--analyze` の `SAGITTAL CHECK` を見る。左右とも ±6°以内なら合格。FFE の保持電流も D10-13D R1（4.7 / 3.2 A）と比べる。
