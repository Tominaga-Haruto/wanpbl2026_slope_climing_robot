## 何が変わったか

1. **関節符号（D10-6）:** LL_HAA・LR_HR・LR_HFE・LR_KFE・LL_FFE の5軸を −1 にしました。目標角と観測値の両方に掛けています。起動した直後に `JOINT SIGNS (motor = sign * H): ...` の行が出ます。
2. **`--sign-pose`:** シムの初期姿勢に、両脚とも HR +8°（爪先を外へ）と HAA +8°（脚を外へ開く）を足した姿勢で保持します。初期姿勢だけだと HR・HAA は 0° なので、この2軸の符号を目で確かめられませんでした。
   - **観測値ではこの確認ができません。** 位置ループは渡された座標系の中で閉じるので、符号が誤っていても、観測値は目標どおりに見えます。確かめる方法は、目で見ることだけです。
   - 保持が終わると `LOOK CHECK` が出ます。各関節について、正しい符号のときの見え方が書いてあります。
3. **D7 の `scan`:** 全10軸の角度を、実機の座標とシムの座標（`H=`）の両方で画面とセッションログに書くようにしました（`scan pos ...` の行）。D10-6 では 45° 未満の5軸がログに残りませんでした。

## 共通の事前条件（毎回）

1. 機体を床から完全に離して吊ります。電源を切る担当が主電源に手を置いておきます。
2. **電源（JESVERTY 2台）:**
   - 2台を並列につながず、片脚に1台ずつつなぎます。マイナス（GND）同士はつないでおきます。
   - 電流制限のつまみは最大、電圧は前回と同じにします。
   - **各 run の間、電源の電流表示の最大値を読み、記録します**（2台それぞれ）。
3. 通電したら、D7 で `scan 3` を打ちます。10/10・`err=0`・`age <= 0.3 s` であることを確認します。
4. 脚を基準姿勢（まっすぐ下、左右平行）に手で持ち、持ったまま `oa`（`YES ALL 10`）→ `scan 3` を打ちます。全軸が `+0.0deg` であることを確認します。
5. run を起動するまで脚を持ち続けます。**最初の `RAMP progress: 0/10s` が出たら手を離します。** そのあとは触りません。
6. 起動した直後の2行を確認します。
   - `ver9_d8_sender build=D10_7_SIGNPOSE_20260923_1430`
   - `JOINT SIGNS ... 0x11 LL_HAA=-1 ... 0x13 LR_HR=-1 ... 0x2A LR_HFE=-1 ... 0x12 LR_KFE=-1 ... 0x2B LL_FFE=-1`
7. CSV の名前は run ごとに変えます（やり直すときは `_a` を `_b` にします）。電源を切ったら、手順3からやり直します。

## 判定（run のあとで基準を変えない）

| | 所見 | 意味 | 次 |
|---|---|---|---|
| **1** | R1 で全関節が鏡像 | 10軸の符号が確定した（通電中に目で確認） | R2 へ |
| **2** | R1 で片脚だけ逆の関節がある | その軸の符号が誤っている | 主電源を切る。方策は回さない。軸を報告し、`robot_joint_map.py` を直して R1 をやり直す |

| **4** | R1/R2 で `current abort` | 保持に上限以上の電流が要る | 主電源を切る。**上限は上げない。** 中止行と `AXIS SNAPSHOT` を報告 |
| **5** | R3 完走・足がぶつからない・`SLEW GAP` が D10-5 より小さい | 符号が原因だった | R4 へ |
| **6** | R3 完走だが、足がぶつかる／左右にバタつく | 符号以外にも原因がある（吊りで接地がないことなど） | R4 は1本だけ。改善しなければ、吊りの診断用に `--lock-haa` を検討する |
| **7** | R4 で左右交互に振れる | 歩容の形が出た | 床上の中止値を R2 の表と R3/R4 の実測から決め、**床上の手順を別に書いてから**床へ |
| **8** | 電源の表示が 1台 10 A に近づく、または電圧が落ちる | 電源が足りない | 床上に進む前に、電源構成（バッテリー、コンデンサ）を見直す |
