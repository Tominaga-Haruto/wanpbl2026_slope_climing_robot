> 作成 2026-09-23。根拠は `../reports/2026-09-23_d10-7_result.md`。

> 異音・接触・支持ずれ・エラー・中止表示が出たら、PC を操作する前に**主電源を切る**。

## 何が変わったか

1. **方策の観測の関節角を `joint_pos_rel`（関節角 − 既定角）に直しました。** D10-7 までは絶対角を入れていたので、方策には HFE・FFE が 10°、KFE が 20° ずれて見えていました。golden.npz と一致することを試験で確かめています。
   - 修正したのは `ver9_integration.policy_snapshot_from_inputs` です。Jetson 用の起動プログラムも同じ関数を通ります。
2. **観測を別ファイルに記録します。** 方策を評価するたびに、観測（42次元）と生の行動（10）を `<CSV名>_obs.csv` に残します。
   - 起動した直後に `INITIAL OBS`（傾き・pos_rel）を表示します。
   - `--analyze` は、この別ファイルがあれば `OBSERVATION` の要約を出します。内容は、傾き（roll/pitch）、並進速度、角速度、指令、pos_rel の平均、行動の平均です。
3. 変えていないもの: 関節符号、中止値、slew、`--gravity-limits`。

## 見方の前提（D10-7 で分かったこと）

- **方策は、シムでも HAA を約 −15°（両脚とも内側）に保って歩きます。** 足を閉じる動き自体は失敗ではありません。見るのは、足同士が強くぶつかって止まるかどうかです。
- 吊った状態では足が地面に着かないので、vx > 0 では空中で脚を漕ぐ動きになるはずです。
- slew（20〜30 °/s）で、方策の要求より動きが遅くなっています（D10-7 R4 では KFE で 143〜155° の差）。

## 共通の事前条件（毎回）

D10-7 と同じです。

1. 機体を吊ります。電源を切る担当が主電源に手を置いておきます。
2. 電源は片脚に1台ずつつなぎ、GND を共通にします。電流制限のつまみは最大にします。**各 run で電源の電流表示の最大値を記録します。**
3. `scan 3` → 基準姿勢で脚を持ったまま `oa` → `scan 3` で全軸 `+0.0deg` を確認します。
4. 最初の `RAMP progress: 0/10s` で手を離します。
5. 起動した直後の行を確認します。
   - `ver9_d8_sender build=D10_8_POSREL_20260923_1530`
   - `JOINT SIGNS`（5軸が −1）
6. CSV の名前は run ごとに変えます。`_obs.csv` は自動で作られます。電源を切ったら、手順3からやり直します。

## 判定（run のあとで基準を変えない）

| | 所見 | 意味 | 次 |
|---|---|---|---|
| **1** | R1/R2 が完走・`SLEW GAP` の KFE が D10-7（R3 64〜89° / R4 143〜155°）より明らかに小さい | 観測のずれが、極端な要求の原因だった | 床上の手順（別に書く）へ進む判断材料にする |
| **2** | 完走したが `SLEW GAP` が D10-7 と同程度 | 吊り（接地なし）が学習の分布の外にある。吊りではこれ以上分からない | 吊りはここで打ち切る。床上の手順を書く |
| **3** | `OBSERVATION` の tilt が 10° を超える、または ang_vel の平均が 0.3 rad/s を超える | 方策は、胴体が傾いている・回っていると見ている（吊り方、または T265 の取り付けの問題） | 吊り方を直して R1 をやり直す。T265 の向きを確かめる |
| **4** | 足同士がぶつかって止まる／引っかかる | 実機の足の間隔が、シムより狭い（推測） | 写真で報告する。吊りの診断専用の `--lock-haa` を検討する |

| **6** | 電源の表示が 1台 10 A に近づく、または電圧が落ちる | 電源が足りない | 床上に進む前に、電源構成を見直す |
