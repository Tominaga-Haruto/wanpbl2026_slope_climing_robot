# D10-3: 吊りのまま「その場保持」で、軸ごとの必要電流を実測する

> 作成 2026-09-23。根拠 `../reports/2026-09-23_d10-2_result.md`。
> 送信器 build **`D10_3_AXISLOG_20260923_1200`**（`.bak_20260923_axislog` あり、テスト 73本 OK）。
> 異音・接触・支持ずれ・エラー・表示された中止は、PC操作より先に**主電源OFF**。

## なぜ歩かせないのか（先に読む）

D10-2 は5本すべて ramp 中に `motion/current abort` で落ちた。止めた軸は **0x11 LL_HAA・0x21 LL_HFE・0x2A LR_HFE・0x22 LR_FFE**。中止時の速度は5本とも **+0.0 deg/s**、位置は原点から ±3° 以内。**暴走ではなく、その場で自重を支えようとして 1.0 A に触れただけ**である。

電流中止 1.0 A は D9 の**1軸 probe**の値で、機体が何も支えていない前提だった。この機体は吊っただけで HAA が 1.70 A、姿勢によっては HFE が 7.36 A を要する。**1.0 A のままでは、方策が正しくても中止は必ず先に来る。**

そこで D10-3 は**方策を回さない**。全10軸を「いま居る位置」に保持させ、軸ごとに次の2つを測る。

- **その軸が自分を支えるのに要る電流** — 中止値を決める唯一の根拠
- **その電流で生じる垂れ角** — 方策が見る関節角の誤差

歩行 run ではこの2つは方策指令と区別がつかない。**測るならこのモードしかない。**

---

## 共通の事前条件（毎回）

1. 機体は**床から完全に離して吊る**。**電源遮断担当が主電源に手を置く。** R1・R2 とも脚は手で支えない（支えると測定値が変わる）。
2. 通電後、D7 コンソールで `scan 3`。**10/10 受信・全 `err=0`・`age <= 0.3 s`** を確認する。
3. **`oa` を打つ前に、脚を手で「まっすぐ下」に整える。** D10-2 では前の run で垂れた姿勢のまま `YES ALL 10` が打たれ、ゼロ姿勢が回ごとに 20〜30° 動いていた。整えてから `oa`、その直後の表示が全軸 `+0.0deg` であることを確認する。
4. 冒頭の `ver9_d8_sender build=D10_3_AXISLOG_20260923_1200` を確認する。違えば実行しない。
5. **CSV名は毎回変える。** D10-2 で ver3 の1回目が上書きで消えた（2度目の再発）。
6. D7 起動時に `USB open失敗 → 再試行 → 成功` が出るのは正常（`../reports/2026-09-23_d10-2_result.md` 末尾）。CANは1フレームも出ていない。2回続けて失敗したときだけ止める。

実行ディレクトリはすべて `C:\Users\harut\Connect2USB2CAN`。

3秒完走してしまった場合は、それはそれで重要な結果である（自重を 1.0 A 以内で支えられている）。その場合 R2 は不要で、D10-2 の中止は別の原因ということになるので、**先へ進まずに報告する。**

## 床上（R5 以降）

**この手順書には床上の run を書かない。** 床上は脚が体重を受けるので、R2 で測った吊りの保持電流では足りない。**R2 の実測表を見てから、床上用の中止値を別に決める。** D10-2 の失敗は「吊りの値で床に下ろした」ではなく「測らずに数字を決めた」ことなので、同じことを繰り返さない。

床上へ行く前に、**立たせた基準姿勢で D7 原点を取るための支持治具**が要る（報告書の該当節）。原点が毎回ちがうままでは、方策は毎回ちがうロボットを見ている。

## 中止

`motion/current abort`、`speed abort`、`stale feedback`、`motor error`、`origin/pre-arm pose abort`、異音、接触、支持ずれ ── いずれも**主電源OFF**。再試行しない。終了時は零MITが自動で送られるが、**電源遮断の代わりにはならない。**

## 事前に決めた判定（走らせる前にここを読む。走らせた後に基準を変えない）

| | 所見 | 意味 | 次 |
