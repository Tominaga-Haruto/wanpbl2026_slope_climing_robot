## ② 基準姿勢はどれか

- **実機:** D7 の `oa` を押したときの姿勢が関節 0°。手順は「脚をまっすぐ下へ、足裏を水平」に手で合わせる。保持の目標は、そこから HFE −10°・KFE +20°・FFE −10°（シムの既定姿勢の数字）。
- **シム:** 関節 0°は、Onshape から URDF を書き出したときの **CAD の組立姿勢**。既定姿勢はそこから HFE −10°・KFE +20°・FFE −10°。
- **CAD の組立姿勢は、まっすぐではなかった**（`robot_sim.urdf` の順運動学。関節の回転中心どうしを結んだ前後方向の角度）:

| | 太もも（前 +） | すね（前 +） | 膝の曲がり | 重心 − 足首（前 +） |
|---|---|---|---|---|
| シムの関節 0°（左 / 右） | +2.9 / −0.9° | −9.4 / −8.1° | **12.3 / 7.2°** | +1.0 / +1.8 cm |
| シムの既定姿勢 | +12.9 / +9.2° | −19.4 / −18.0° | 32.3 / 27.2° | **+1.5 / +2.3 cm** |
| 実機の保持姿勢（原点がまっすぐな脚の場合） | +10.0 / +10.1° | −10.0 / −10.0° | 20.0 / 20.0° | **+0.1 / +0.2 cm** |

- 左右で膝の曲がりが 5°違うので、CAD の組立で左右の脚が同じ角度に置かれていなかった可能性がある。
- **ご提案の「初期姿勢を CAD（まっすぐ直立）に合わせる」は、「実機の原点を CAD の組立姿勢に合わせる」と同じ意味になる。** ただし CAD の姿勢はまっすぐではないので、まっすぐに合わせるとシムと 7〜12°ずれる。
- 対応として、build `D10_13D_ZEROOFFSET_20260923_2300` に `--zero-offset cad_fk` を入れた（「まっすぐ」の原点から CAD の関節 0°への固定の差を足す）。**前提は2つあり、どちらも未確認:** D7 の姿勢が「回転中心が一直線・足裏が胴と平行」であること、CAD の姿勢でも足裏が胴と平行であること。**Onshape で膝の角度を測れば確かめられる。**

## ③ 前は立てていたのに、何か変えたか

保持の段階のコードは、D10-13（build `D10_13_FLOORWALK_20260923_1800`）から変えていない（差分は `_timing.csv` に書く行だけ）。D10-13B 以降に足したのは、どれも付けたときだけ効くフラグである。違ったのは紐と手の使い方で、D10-13 の 18 時台は足裏が床に平らでなく、紐か手で支えられていた（`2026-09-23_d10-13b_result_シムと実機の点検.md`）。

## ④ 原点合わせが厳しすぎる

- 起動時の拒否（`ALL-AXES PRE-ARM GATE refused ... delta=+33.5deg`）は原点の精度ではなく、**起動時の脚の位置が保持姿勢から 30°以上離れていた**という意味だった。メッセージが「`oa` をやり直せ」と言っていたのが誤解のもと。
- D10-13D から、保持姿勢へ 10 s かけて ramp する run は 45°まで許す（方策の目標へ直接 ramp する場合は 30°のまま）。メッセージも「脚を保持姿勢の近くに持って起動し直す。`oa` は不要」に直した。
- 方策中の「原点 45°」の中止は、関節が原点から 45°を超えたという意味で、原点がずれたという意味ではない。メッセージを直した。
- `oa` をやり直す必要があるのは、電源を切ったあと（または `scan` で原点がずれて見えたとき）だけ。
