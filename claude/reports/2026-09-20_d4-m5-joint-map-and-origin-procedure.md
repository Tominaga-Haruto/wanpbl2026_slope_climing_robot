## D4の実施内容 2 の意味

基準姿勢（全H角 = 0）で各IDに `o 0` を送ったなら、各軸の変換は次だけになる。

```
q_H[i] = +1 * q_MIT[CAN_ID[i]]
q_MIT_target[CAN_ID[i]] = +1 * q_H_target[i]
```

すなわち、CANの並びで受け取った角度をH順に並べ替えるだけで、方策の10関節角になる。Hの歩行開始既定角は HR/HAA=0、HFE/FFE=-0.1745 rad、KFE=+0.3491 rad である。電源断後はこの変換の前提となる `o 0` を同じ物理基準姿勢でやり直す。

## 全10軸を原点化する安全手順

これはモーターの電気的な絶対原点を探索する作業ではない。Hのゼロ姿勢を、その起動中のMIT/サーボ座標のゼロに対応付ける作業である。`o 0` は軸を動かさない。`morg`、`overify`、`jog`、`hold`、`step` は使わない。

1. 主電源を切り、ロボットを吊るか機械的に支持する。手で支えるだけでは始めない。主電源の遮断を手元に置く。
2. CADの全ゼロ姿勢（脚をほぼ真下、爪先をbaseの+X、足裏をほぼ水平）を作る。正面・左右・上面写真、支持点、再現に使う寸法を記録する。次回同じ姿勢を作れないならここで止める。
3. USB2CANを接続し、電源を入れる。数秒待ち、フィードバックが来るまで指令を送らない。
4. PowerShellで `cd C:\Users\harut\Connect2USB2CAN`、`py -3.13 motor_console_ver8.py` を実行する。起動後に `log on`、`sniff 3` を実行する。10台の定期フィードバック、`err=0` を確認する。欠け、err、異音、支持のずれがあれば主電源を切って終了する。
5. 以下のH順で、各組について `id <dec>`、`model <機種>`、`s`、`o 0`、`s` を行う。`s` で新鮮なフィードバックと `err=0` を確認してから `o 0` を送る。`o 0`後の表示を画面ログへ残す。

```
id 19 ; model AK10-9 ; s ; o 0 ; s
id 28 ; model AK10-9 ; s ; o 0 ; s
id 27 ; model AK10-9 ; s ; o 0 ; s
id 17 ; model AK10-9 ; s ; o 0 ; s
id 42 ; model AK80-9 ; s ; o 0 ; s
id 33 ; model AK80-9 ; s ; o 0 ; s
id 18 ; model AK10-9 ; s ; o 0 ; s
id 26 ; model AK10-9 ; s ; o 0 ; s
id 34 ; model AK80-9 ; s ; o 0 ; s
id 43 ; model AK80-9 ; s ; o 0 ; s
```

PowerShellでは `;` はコマンド区切りではあるが、コンソール内部では1行ずつ入力する。上の各行を分割して順に打つ。

6. 完了後に `q` でコンソールを終了する。電源断後は原点が残ると仮定せず、次回も手順1から行う。位置指令・方策送信はこの手順の対象外である。

## ゲイン表の状態

H成果物の stiffness/damping は既に得られており、機種別の係数も実測済みである。従ってD4の実施内容4の算術は可能だが、AK80-9のHFEは `15 / 0.523 = 28.7` となり、現行ver8の安全上限Kp=20を超える。よって「10軸のMIT Kp/Kd上限を実装・安全確認済み」という意味では未完了である。Kp/Kd換算値を得るための治具は不要だが、この上限の扱いはver9の安全設計で決める。

## Kt治具との区別

Kp/Kdの逆算は、実効係数（AK80-9: c_p=c_d=0.523、AK10-9: c_p=1.258、c_d=1.216）からでき、治具は不要である。一方、Ktは「指令トルク値または電流が実際に何 N*m か」を外力で測る量であり、重り・アーム・固定治具が必要である。H方策の通常MIT指令はトルク欄を0にするため、KtはKp/Kd変換そのものの前提ではない。ただしトルク飽和・電源余裕・物理的な安全余裕の評価には残る。
