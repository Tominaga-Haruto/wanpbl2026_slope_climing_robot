# 2026-09-22 D9-4 結果: 足先の左右接触を確認。判定 A（機構）

> **最新は末尾の「追記（同日・D9-5A 実施後）」。本文の主結論「D9-3 は足どうしの突き当たりを押していた」は、正方向 +6.5° でも動かなかったため取り下げた。読むときは追記を先に読む。**

対象 0x1C（LL_HR、AK10-9）。主電源OFF・吊り支持のまま、ユーザーが目視と手回しで確認した。

## ユーザーの所見（そのまま）

- **完全に吊った状態で、左右の足先がほんの少し触れあっている。**
- リンク・スペーサ・ケーブル・支持具の接触、締結、ケーブルの張り、その他は問題なし。

## 判定

引き継ぎ書 `../handoffs/2026-09-22_d9-4_無通電機構確認.md` の判定表では **A（干渉・当たりが見つかった）**。
ただし A の想定（組付け不良・ケーブル張り）とは中身が違う。**ぶつかっているのは相手の足であり、0x1C 自身は壊れていない可能性が高い。**

## 原因の分析

### 1. D9-3 が押した向きは、足どうしが近づく向きだった

- `robot_model_conventions.md` §2: **HR の正方向 = 爪先が外を向く。**
- `2026-09-20_d4-m5-joint-map-and-origin-procedure.md`: 全軸「時計回り = 実機の正方向」で、**実機→H 符号は +1**。よって実機の符号も「正 = 爪先が外」。
- D9-3 の要求角は **−6.50°**。0x1C は LL（左脚）なので、**負 = 爪先が内向き = 左足が右足へ寄る向き**である。
- 足先が既に触れているなら、この向きは**最初から硬い突き当たりに当たっていた**。

### 2. 実測の形が「突き当たり」と一致する

D9-3 の生データ（`2026-09-22_d9-3_result.md`）:

| 実測 | スティクション（静摩擦）なら | 突き当たりなら |
|---|---|---|
| 正味変位 0.200°（2目盛）で止まり、以後5秒完全静止 | 電流が上がると**急に滑り出す**（不連続に動く） | **弾性たわみとバックラッシュを取り切った分だけ動いて止まる** ← 一致 |
| 0.86 A を10秒保持しても増えない | 滑り出した後は電流が落ちる | 押し続けても動かない ← 一致 |
| 実行後 `scan` で 0.2° が戻っていない | — | 押し付けたまま零MITで解放 → バックラッシュ分が残る ← 一致 |
| MITトルク経路は正常（7.96 A/rad、比 1.00） | — | 電気側は無罪 ← 一致 |

「0.86 A を掛けても 0.2° しか動かない」は、**不感帯 6.2° の静摩擦**よりも、**0.2° で物に当たった**と読むほうが素直である。裸の AK10-9 の動き出し電流は 0.63 A 級（`2026-09-22_d9-0x1c-current-vs-error.md`）で、6.2° 相当の摩擦は桁が合わない。

### 3. したがって D9-3 の判定 C は「0x1C の不感帯は 6.2°以上」を意味しない

正しくは **「0x1C は負方向（爪先内向き）に 0.2° しか動けない機械的余地しかなかった」**。
不感帯 6.2° という数字は、**接触を取り除くまで摩擦の値として使ってはいけない。**
学習側の「実機の不感帯はシムの5倍」という持ち帰りも、**根拠が弱くなったので保留**とする（friction スイープ自体は別の理由で有効なので続けてよい）。

### 4. まだ決まっていないこと（ここを次で測る）

**どちらの符号が塞がっているかは、接触点が爪先側か踵側かで決まる。** HR の回転軸は脚に沿ったほぼ鉛直軸で、足は前後に長い（約 0.17 m）。軸まわりに回すと爪先と踵は逆向きに動くので、

- 接触が**爪先側**なら、負（爪先内向き）が塞がり、正は自由。
- 接触が**踵側**なら、正が塞がり、負は自由。

D9-3 が負で止まった事実は前者を示唆するが、**推測で確定させない。** 次の D9-5 で、まず無通電の手回しで直接見る。

### 5. もっと重い問題: ゼロ姿勢で足が触れている

D7 の原点設定（2026-09-20 18:47）は「最終構成を基準姿勢で機械固定した状態」で行われた。つまり **H のゼロ姿勢＝いま足先が触れている姿勢**である。
シムのゼロ姿勢は「脚がほぼ真下・爪先 +X・足裏水平」で、左右の足は離れている前提である。方策は HR を左右に振る。**ゼロ姿勢で既に接触しているなら、方策は片側へほぼ動けない。**

これは 0x1C の診断とは別に、**床上デプロイの前に必ず解く課題**である。次のどれかが起きている:

- 組み上がりが CAD と違う（股幅・HAA の実角・脚の取り付け）。
- D7 のときに作った「基準姿勢」が CAD のゼロ姿勢と違っていた（内股側にずれていた）。
- CAD のゼロ姿勢自体で足が接触寸前である（設計の余裕不足）。

**やること:** CAD のゼロ姿勢での左右足先の最短距離を出し、実機で同じ寸法を測って比べる。差が出た側が原因である。これは実機に通電しないので、いつでもできる。

## 追記（同日・D9-5A 実施後）: 接触仮説は取り下げ。支持のしかたが次の容疑者

D9-5 段階1-A（`--motor-id 0x1C --probe-target-deg 6.5`）を実施した。**保存された CSV は判定 C である。**

`C:\Users\harut\Connect2USB2CAN\logs\d9_5a_free_dir_0x1c.csv`（500行）を `--analyze`:

| 項目 | 値 |
|---|---|
| 向き | **+6.50°（正・爪先が外）** |
| 開始位置 | **+7.90°**（手で脚を外へ開いた状態） |
| フィードバックがとった値 | **+7.9 / +8.0 の2つだけ** |
| 正味・持続変位 | **+0.100°**（量子化1目盛） |
| 保持 \|I\| | **0.86 A**（ピーク 0.97 A） |
| 非ゼロ速度 | 500サンプル中 **1個**、最大 0.006 rad/s |
| `TORQUE PATH` | 8.21 A/rad、指令Kp比 1.03、**verified** |
| 判定 | **C** |

**したがって 0x1C は正負どちらの向きでも 0.86 A で動かない。足どうしの接触では説明できない。** 本文 §1〜§3 の「D9-3 は突き当たりを押していた」は取り下げる。

### ただし打ち消してはいけない事実が2つある

1. **ユーザーは複数回実行しており、「動いた」と見えたのは手で支えて角度を調整していた回である。** CSV名が固定だったため、その回のログは最後の回に上書きされて残っていない。**残っている証拠は「動かなかった」ものだけ**である。
2. **吊ると脚は自分で内側へ閉じ、足首のあたりで左右がぴったり合わさる。** この姿勢では HR の回転軸が傾き、足どうしが横から押し合う。**手で支えるとその荷重と摩擦が消える。** 「手で支えたら動いた」は、それで説明がつく。

よって次に潰すのは**接触そのものではなく支持のしかた**である。手順 `../procedures/d9_6_支持を直してHRとFFE_実験手順.md`。

### 本文 §5 の訂正

**「ゼロ姿勢で足が触れている」は誤りである。** ゼロ点は**立たせた状態**で合わせてあり、その姿勢では足は離れている。以後電源を切っていないのでそのゼロは有効である。足の接触は**吊ったことによる姿勢**であって、ゼロ姿勢の問題ではない。§5 の「ゼロ姿勢で足が接触している」を前提にした課題は取り下げる。

### 新しく実測で分かったこと: HR の機構的可動域は左右非対称

主電源OFFの手回しで測った 0x1C（LL_HR）の可動域:

| 向き | 可動 | 止める要因 |
|---|---:|---|
| 外（正・爪先が外） | **約 90°** | — |
| 内（負・爪先が内） | **約 45°** | **配線の長さ** |

URDF は全関節 lower/upper = ±π のままである（`robot_model_conventions.md` §4 の「実際の機構的可動域はまだ入れていない（宿題）」）。**方策が内側 45° を超える HR を出すと配線を引っ張る。** 床上デプロイ前に URDF／シムの可動域へ入れる。`.*HR` の実測値としては初めての数字である。

### 実験のやり方として直すこと

- **走行中に手で機体を支えない。** 手の摩擦が測定に入り、脚が回ったのか手が動いたのか区別できない。
- **機体本体の回り止めを付ける。** HR にトルクを入れると反作用で機体が吊り紐ごと回る。D9-5A の「動いた」はこれを見ていた可能性が高い。
- **CSV名を毎回変える。** 固定名で複数回走らせると、いちばん見たい回が消える。今回それが起きた。
