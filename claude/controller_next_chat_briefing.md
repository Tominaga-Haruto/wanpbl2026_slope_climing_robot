# Jetson コントローラー次チャットへの指示書（2026-09-18）

## ゴール

**直結時のみ完了（2026-09-20）:** Jetsonに有線直結したSwitch 2 Proは、**モーター/CAN/ONNXへ接続せず**に50 Hzで読み、左スティックから画面・CSVだけに `(vx, vy, 0)` を出す乾式確認を終えた。実運用に必要な変換ケーブル経由ではUSB設定に失敗するため、D5は未完了。ユーザー判断（2026-09-20）により、実運用の第一候補をBluetooth無線へ切り替えた。無線の乾式受入手順は `reports/2026-09-20_d5-wireless-dry-run.md`。詳細な有線失敗は `chats/2026-09-20_d5-extension-path-handoff.md`。

## 確定した実測

- Jetson: Linux 5.10.216-tegra / aarch64。
- 入力は `Microsoft X-Box 360 pad`、USB ID `045e:028e`。
- 安定入力パス: `/dev/input/by-id/usb-045e_XBOX_360_For_Windows_000000000001-event-joystick`。`event2` は現時点の番号であり、コードに固定しない。
- 左スティック: `ABS_X` (0)、`ABS_Y` (1)、範囲 -32768〜32767。中立は概ね X=0 / Y=-1。
- A: `BTN_SOUTH` (304)、Y: `BTN_WEST` (308)。今回は使わない。
- 仮デプロイは左スティックだけの並進。A/Y旋回は、旋回方策を別途用意してから乾式試験する。
- 通常ターミナルの専用venv `~/.venvs/controller-d5` に `evdev` を導入済み。Jetson側Codexの実行環境には`/dev/input`が見えないため、実機入力の試験には通常ターミナルを使う。
- 中立約10秒・前後左右・抜線・再接続を実測済み。前=`+vx`、後=`-vx`、右=`-vy`、左=`+vy`、`wz=0`。抜線は`Errno 19`でプローブが終了し、再接続後はゼロから起動した。
- **実運用の未解決:** 変換ケーブル経由では`057e:2009`（Pro Controller）が`can't set config #1, error -32`で再接続を繰り返し、ゲームパッドの`/dev/input`が作られない。ユーザーの無線優先の判断により、Bluetoothを乾式で検証する。USB IDや有線と同じデバイス名は要求しない。Bluetooth接続済みで安定した`/dev/input/by-id/*-joystick`のパスを得て、直結時と同じ中立・4方向・抜線・再接続をCAN等未接続で通した場合だけ、D5を完了とする。Bluetooth未使用時の代替は、直結時と同じ`045e:028e`として安定認識するUSBデータ対応の延長経路である。

## D8で再開するときの確認

Jetson通常ターミナルで、専用venvと安定パスが引き続き使えることだけを確認する。パッケージ導入は不要。

```bash
pwd
~/.venvs/controller-d5/bin/python --version
~/.venvs/controller-d5/bin/python -c "import evdev; print(evdev.__version__)"
ls -l /dev/input/by-id/usb-045e_XBOX_360_For_Windows_000000000001-event-joystick
```

- `evdev` が無い・安定パスが無い場合は、統合へ進まず原因を報告する。
- D8では、既存のCAN制御プログラムとは別に、受け手側が入力更新時刻を監視できる境界を作る。

## `pad_probe.py` の要件

- `evdev`で安定パスを読む。CAN、`can` モジュール、ONNX、モーター制御コードはimportしない。
- 50 Hzで標準出力とCSVへ時刻・生のX/Y・正規化値・`(vx, vy, 0)`・状態を出す。
- デッドゾーンは最初は0.05以上にし、実測ログで調整する。
- `ABS_Y` の前後符号と `ABS_X` の左右符号は、方策のbase座標契約を確認してから決める。推測で確定しない。
- スティックを離したら必ず `(0, 0, 0)`。指令上限は画面上の仮値として `vx ±0.3`、`vy ±0.2` を超えない。
- 現行プローブは無イベントで`timeout`・ゼロを表示するが、抜線の読取例外ではexit 3で終了する。統合ループでは受け手側が入力途絶を検出し、ゼロ指令と安全停止を継続する。
- 本番の非常停止は物理的なモーター電源遮断を手元に置く。今回の乾式プログラムにCAN送信や解除機能を加えない。

## 乾式テストの順序

1. D5の乾式確認は完了。D8では速度コマンドをver9の入力境界へ接続する。
2. 入力更新が200 msを超えたら、受け手側でゼロ指令と安全停止を継続する。
3. CAN送信を含む安全性の確認はD9以降に分離する。

## 禁止事項

- モーター通電、CAN送信、ONNX推論、T265との統合。
- 右スティック、十字キー、トリガー、肩ボタン、HOMEを本番操作に割り当てること。
- モデル、重み、生ログをGitへ追加すること。
