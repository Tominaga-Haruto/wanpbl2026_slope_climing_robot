## 最初の仕事

**ユーザーが `../../procedures/d10_6_関節符号_無通電確認手順.md` の表（10軸の読みの符号と、どちらが前か）を貼る。期待符号と照合し、不一致の軸を確定する。** 不一致があれば送信器に実機→H 符号を実装する（下記）。**確定するまで方策 run・MIT 送信はしない。**

## 状況

- **左右に同じ関節角を送ると、見た目は脚が前後に割れる**（D10-3〜D10-5 で毎回。エンコーダ上は両脚とも同じ角度）。シムの URDF では HFE・KFE・FFE の軸が左右とも +y なので、同じ角度＝左右対称のはず。**片脚のピッチ3軸の符号が逆（D4 の全軸 +1 が誤り）の疑いが強い。** 軸の向きの表は報告書にある。
- これが正しければ、D10-3〜D10-5 の方策 run は片脚の符号が逆のまま回していた。方策の外れた要求（KFE +178°）や足同士の衝突もこれで説明できる（推測）。
- **初期姿勢の保持電流は実測済み**（LL_HFE 1.80 A、LR_HAA 1.2 A、LR_HFE 1.1 A、KFE 0.7〜0.87、FFE 0.65〜0.82 A）。1.0 A 中止では立った姿勢すら保てない。床上の中止値はこの表と方策 run の実測（最大 LR_HFE 4.4 A）から決める。ただし符号を直すと姿勢が変わるので、**符号修正後に D10-5 R1（`--stand-only`）を取り直す。**
- `oa` の運用: 基準姿勢で持ったまま `oa` → `scan 3` → run の最初の `RAMP progress` の後で手を離す（本人の指摘で確定）。

## 符号の実装方針（D10-6 で不一致が出たら）

- `robot_joint_map.py` の `JointBinding` に `sign`（+1/−1）を足すのが正本。D4 報告書の表も同じ commit で直し、D4 報告に訂正1行。
- 送信器では**目標（H→実機）と観測（実機→H：位置・速度）の両方**に掛ける。`frames()`/`wire_command()`、`servo_feedback_to_h_units` 周り、CSV の記録（どちらの座標系で書くかを列名で明示）、`--analyze`、1軸 probe の符号判定（`DEMONSTRATED_STALL_CURRENT_A` の方向はモーター座標のまま）を洗う。電流の符号も同様。
- テスト: 符号 −1 の軸で「H の +10° が実機 −10° で送られ、実機 −10° の読みが H +10° で観測される」往復テスト。
- ver9 のほかのモジュール（`ver9_integration.py`・`ver9_shell.py`・`ver9_jetson_deploy.py`）も同じ変換を通っているか確認する。Jetson 側に同じバグを残さない。
- `.bak_YYYYMMDD_jointsign` を取る。build 名を変える。

## ユーザーの提案（保留中）

- 「吊り中はずっと左右方向を手で支える」「HAA を初期姿勢に固定する／可動範囲を狭くする」: **符号を直してもまだ足同士がぶつかるなら**、吊りの診断専用に `--lock-haa`（HAA を初期姿勢に固定）を足すのはあり。床上では使わない（方策は HAA で平衡を取る）。手で支えると電流の測定が汚れるので、測定 run では支えない。
