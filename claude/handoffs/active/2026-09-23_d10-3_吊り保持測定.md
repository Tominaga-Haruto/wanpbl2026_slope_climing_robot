## ユーザーからの質問への答え（D7 の USB open 失敗）

```
接続: ch=0 ...（受信開始、まだ送信なし）
USB open失敗。送信せず1.5秒待って1回だけ再試行します。
GsUsbBus was not properly shut down
接続: ch=0 ... / 接続: ch=1 ...
```

**危険ではない。** `logs\d7_origin\session_*.txt` に実体が残っている: `open FAILED attempt=1: USBError: libusb0-dll:err [reset] could not reset device, win error 31`。gs_usb は `Bus()` 構築時に USB インターフェースをリセットし、このPCではそれが1回目にほぼ必ず失敗する。失敗経路は `bus.close(stop_motors=False)` を通るので **CANフレームは1本も出ていない**。`GsUsbBus was not properly shut down` は、コンストラクタが例外で巻き戻る途中の python-can のファイナライザ警告で、実害は無い。

**ただし margin がゼロだった。** 1回目が常に失敗する以上、2回しか試さない設計は「予備がない」に等しく、もう一度ゆらげば D7 が起動しない。**`OPEN_ATTEMPTS` を 3 にした。** 挙動は変わらず、予備が1回戻る。送信器 `DualBus.open` も同じく 2→3。
