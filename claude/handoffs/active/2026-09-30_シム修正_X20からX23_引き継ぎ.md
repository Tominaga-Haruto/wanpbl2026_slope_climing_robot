見立て（どれも推定、数字では未検証）:
- X20 の立往生: 接地の 0/1 だけでは足の上げ方の手がかりが無い（立っていても gait_contact の約 55%）、4 cm は股 25°・膝 50°程度が要る、
  4番目 0°で足首の間隔が約 33 cm（URDF）なのに 4番目を閉じる動きを hip の罰が止めていた。
- X21b の二段階: 参照の振り足は真上に上げ下げするだけで前へ運ぶ成分が無い（FK で前後 0 mm）。
- X22 のつま先立ち: 振り足の高さを床からの高さで測っているので、軸足のつま先立ちで体ごと上げるのが安い。
- X22 の外側の接地: 足首にロールの関節が無いので、4番目で脚を閉じると足裏も傾く。胴を軸足側へ傾けない限り、狭い間隔と平らな足裏は両立しない。
  → feet_flat を入れると、足の間隔が少し広がるか胴が左右に揺れる歩き方になりうる（本人に確認してもらう点）。
- mp4 が速く、画面の再生が遅く見えたのは、画面が実時間より遅く描いているだけ（本人も Isaac Sim が重かったからと）。

## 4. 決まり・注意

- WRS の CLI には、**新しいチャットに貼る自己完結プロンプト**を書く（本人の希望、トークン節約）。「CLI に渡すもの」と、コードを足すなら「追記するコード」。
  学習・再生・動画のコマンドは本人が別々の PowerShell で前景実行。CLI は学習コマンドを先に出してから残りの作業へ。
- 再生で見るときは、指令を固定（vx 0.3）とランダム（カニ歩き等を見つける）の両方。動画は上書きしない名前で何度でも（x23_video.py）。
  立って止まった所から映す（最初の 2 s は指令 0）。
- stand_env_cfg.py は WRS でハードリンク。Edit ツールを使わせない（python の r+ で書き換え、inode を確認）。
- 足の高さ FOOT_Z_STAND = 0.079 は X20 の S1 で「最初の 1 step」（落下中）に測った値で、落ち着いた値は約 0.075（X23 の測定）。
  振り足の目標が約 4 mm 高めになっているだけで、学習中の run の途中では変えない。
- 符号（robot_sim.urdf の FK、2026-09-30）: +3番目 = 股を後ろへ、+2番目 = 膝を曲げる、3番目・2番目・1番目のどれを +10°しても足裏が +10°。
  足の座標では重力がほぼ ±y（左右で符号が逆）。
- X21 以降の方策の観測は 44 次元（H の 42 の後ろに sin・cos(2π t / 0.7)、t = 方策開始からの tick × 0.02 s）。時計は指令 0 でも進む。
  既定姿勢: X21a/X22a/X23a はまっすぐ寄り（左 −2.6 / −4.3 / +6.9、右 −6.4 / +0.8 / +5.6 deg）、b 系は H（−10 / +20 / −10）。
- 時計の汎用性: 周期は固定で、速さは歩幅で変える（0.6 m/s で 1 歩約 21 cm）。学習した指令の範囲（vx −0.2〜0.6、vy ±0.1、wz ±0.3）の中なら対応。
- Kt は当面測らない（方針の引き継ぎ §3c）。分銅なしなら、脚を水平にして重力のトルクと比べる方法が一番確実（本人に説明済み）。
- 文書リポジトリで `git add -A` やフォルダ指定をしない。VM から commit するとロックファイルが残るので、削除の許可（device_request_delete_permission）を取って消す。
  VM からは push できない（認証なし）ので、本人に `git push origin main` を頼む。
