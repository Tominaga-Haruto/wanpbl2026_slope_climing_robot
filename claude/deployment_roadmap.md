# 平地デプロイまでの全体工程

> ゴールは、まず平地で「吊り試験を経て、全身を安全に下ろして方策で動かす」こと。坂登坂と安定したその場旋回は次段階であり、この工程の完了条件には入れない。
>
> 詳細な数値は学習側を next_chat_briefing.md、実機側を next_chat_briefing_motor.md、コントローラー側を controller_prep_briefing.md の正本とする。この文書は依存関係と完了条件だけを持つ。

## 0. 今どこまで来たか

- シミュレーション: 平地の第一候補は H_eff13p5@2999、予備は G_real_peak@2999。小旋回を含む評価は合格している。WRSでパッケージ化と、より頑健な P_gainDR_narrow の判定を進めている。
- 入力: JetsonでSwitch 2 Proの有線認識と左スティックの生値は確認済み。読み取り専用の pad_probe.py は作成済みだが、Jetson上での50 Hz・抜線試験は未完了。
- モーター: MIT位置指令、機種別Kp/Kd換算、50 Hzの予定表は確認済み。全10台のID・機種・関節・正方向はユーザー設定済みで、H順への並べ替えも作成済み。デプロイ用の全軸原点は未設定。
- センサ: T265はWindowsで200 Hz取得とbase座標への変換が確認済み。ロボットへの取付け・位置補正は未実施。
- 統合: Hの42観測組立・ONNX推論・H順10目標角のCAN非接続部品とgolden照合は実装済み。T265の実機取付け値、10軸の原点／ID変換、ver9の入出力・停止・CAN送信は未実装。

## 0b. 今ユーザーが進められること

原点設定を今行う必要はない。部品を外す・付ける、モーター単体の実験、配線変更でモーター軸が動く可能性があるため、デプロイ用の `o 0` は最終構成を固定するまで延期する。

1. **部品取外しを伴うモーター実験を先に終える。** Kt測定を行うなら、重り・アーム・固定治具を準備してAK80-9／AK10-9単体で行う。治具が無い間は保留し、脚付き全身を代用しない。
2. **T265を機体へ取り付ける。** 正面開口へレンズ前向き・水平で固定し、CADで確定したtracking center候補（waist右端から左へ234.000 mm、下辺から上へ67.750 mm）を記録する。base原点への変換と奥行きを測って `R_OFFSET` を確定する。既存の前向き・水平の5動作CSVは再利用し、取付け向きが異なる場合だけ再取得する（D3/M6）。
3. **最終組立て前の準備をする。** 10軸のID・機種・H順の設定、ver9の停止設計、`mit_sim`、コントローラー乾式試験を進める。これらは原点なしで進められる。
4. **最終構成を固定する。** 以後に外す予定の部品・配線変更を終え、原点姿勢を再現できる支持方法、写真、寸法を準備する。
5. **この時点でM5を実施する。** 吊るか寝かせて脚をまっすぐにした基準姿勢で、全10台に `o 0` を設定する。電源断、軸の回転、部品脱着後は再設定する。
6. **原点設定の直後に初めて実機位置指令へ進む。** 1モーター → 片脚 → 全身の順を守る。方策送信は、ver9の停止処理、`mit_sim`、10軸＋推論の50 Hz試験、各途絶停止試験を終えた後だけ行う。

## 1. 学習側: 実機へ渡せる方策を確定する

### 作業

1. WRSの夜間・追加学習を評価する。
2. P_gainDR_narrowが既定基準、stiffness x0.7で転倒5%以下、H_eff13p5に無い不合格なしを満たすか判定する。満たさなければH_eff13p5@2999を第一候補のままにする。
3. 第一候補と予備を、実機用パッケージに出す。

### 完了物

- ONNX方策
- golden npz（既知の観測を入れた時の正しい行動）
- obs_contract.md（42観測の並び、正規化、50 Hz、10行動の並び、action scale 0.5）
- 関節グループ別 stiffness / damping / effort
- SHA256
- DEPLOY_README.md

### ここでの注意

- ONNXがあるだけでは不十分。観測の順番・尺度が1項目でも違えば実機では別の方策になる。golden npzでver9の入出力を照合する。
- その場旋回はデプロイの必須条件ではない。実機初回は左スティックの並進だけに固定する。

## 2. 入力側: コントローラーを安全な速度指令にする

### 作業

1. Jetsonでpad_probe.pyを動かし、中立10秒、全方向、50 Hz、USB抜線、再接続をCANなしで記録する。
2. obs_contract.mdを見て、左スティックの前後をvx、左右をvyへ割り当てる符号を決める。
3. teleop.pyでデッドマン、非常停止ラッチ、200 ms入力途絶時の停止、変化率制限を実装・乾式試験する。
4. ver9とのプロセス境界を決める。受け手側にも200 ms途絶で停止を実装する。

### 完了条件

- スティックを離す・ケーブルを抜く・読取例外のどれでも、出力がゼロへ遷移する。
- 物理非常停止はコントローラーのボタンではなく、手元のモーター電源遮断である。
- 初回の範囲はvx ±0.3 m/s、vy ±0.2 m/s、wz=0。

## 3. 実機の前提を揃える

### 3-1. 方策に必要な関節設定

- WRSのアクチュエータ表と実測の機種別係数から、10関節それぞれのMIT指令Kp/Kd上限を表にする（M4）。
- 各関節を決まった姿勢で原点化し、シムの初期角 HR 0 / HAA 0 / HFE -0.1745 / KFE 0.3491 / FFE -0.1745 rad との対応、可動域、ソフトリミットを表にする（M5）。

  **実施時期:** M5の物理的な `o 0` は、部品脱着・単体実験・配線変更を終え、構成を固定した後、最初の1モーター位置指令試験の直前に行う。原点設定後に軸を動かしたり電源を入れ直したりしたら、同じ基準姿勢で再設定する。

### 3-2. T265

- 実機での取付け向きと位置を決め、R_CBとR_OFFSETを確定する。
- ロボットに載せて振動・吊り下ろし時のconfidenceと途絶を測る（M6）。

### 3-3. 未解決の物理安全項目

- KtをAK80-9とAK10-9で測る（M3b）。現在は重り・アーム・**固定治具が無い**ため保留。脚付き全身を代用した測定はしない。
- 10モーターの合計電流、突入電流、電源容量を確認する（M9）。

## 4. ver9を乾式で完成させる

ver9は50 Hzで、全モーターフィードバック、T265観測、コントローラー指令から42次元観測を作り、ONNXの10次元行動を目標角へ変換し、10台へMIT指令する。

必須の停止条件は、CAN受信途絶、T265途絶・低confidence、コントローラー途絶、motor err、関節ソフトリミット越えである。各条件で零指令を複数回送ったうえで、定めた停止姿勢または脱力へ移る。

実機CANへつなぐ前の完了条件:

1. golden npzでONNX入出力が一致する。
2. mit_simで10関節分の指令、上限、停止処理を再生できる。
3. ONNXと10台CAN送信を含めても50 Hzの周期乱れを確認する（D3）。
4. 入力・T265・CANを個別に途絶させ、すべて停止へ遷移する。

### §4 の実装状況（2026-09-19）

- `C:\Users\harut\Connect2USB2CAN\policy_integration.py` は、Hの契約順で42次元を構成し、署名照合済みパッケージのONNXから10 action、既定姿勢 `+ 0.5 × action` のH順10目標角を作る。golden 500件で観測組立、action、目標角を照合済みで、CAN・T265・コントローラーはimportも接続もしない。
- D3の実機取付け後に確定する `R_CB`／`R_OFFSET` と、D4/M5の全10軸のCAN ID・符号・原点変換表は未記録である。これらを推測して実機順に変換しない。
- したがって、`mit_sim`への10目標角の投入、10台CAN IDへの逆変換、ゲイン表の適用、50 Hzの統合周期・停止処理は未着手である。D2のver9骨組みと、D3/D4/M5の確定成果物を受けてから実装・試験する。

### 学習と並行できること／待つもの

- 学習中でも、D2のver9骨組み、Jetson上のコントローラー乾式試験、T265取付け・座標確認、ID/H順の設定表、`mit_sim`、Kt用治具・電源容量の準備は進められる。M5は原点姿勢の支持方法・写真・寸法だけを準備し、物理的な`o 0`は最終組立て後まで延期する。

## 5. 段階的な実機デプロイ

1. 1モーターを吊った状態で、原点・上限・停止処理を確認する。
2. 片脚を吊った状態で、複数関節の符号・指令・停止を確認する。
3. 全身を吊った状態で、指令ゼロの立位、低速並進、停止を確認する。
4. 全身をゆっくり下ろし、まず指令ゼロで安定するかを見る。
5. vxを小さく入れ、前進・停止・横移動を一つずつ確認する。

各段階で異音、err、温度急上昇、想定外の運動、停止失敗があれば電源を切り、前段へ戻る。

## 6. 平地デプロイ後

- 長時間の歩行、温度、電源余裕、観測途絶への頑健性を確認する。
- 小旋回を実機で確認する。安定したその場旋回は別方策の検証対象。
- 平地で再現可能になってから、坂の地形・報酬・実機試験へ進む。
