## 0. 実験の考え方（ユーザー案「全部入り → 良ければ1つずつ抜く」への評価）

**方針は妥当。ただし4点を足す。**

1. **全部入り（B）と同時に、最小変更（A: 08-21 版＋`noise_std_type=\"log\"`）を並走させる。**
   カニ歩きの最有力原因（base の向き）はすでに直してあり、**B から1つずつ抜いても「base の修正だけで十分だったか」は分からない。** A がその対照になる。24.5 GB あるので 2〜3 本並走できる見込み（4096 env の VRAM は未測定。起動時に測る）。
2. **全部入りに入れるのは「直す系」だけ。「縛る系」（アクチュエータの実機化・effort 定格化・friction 実測値）は入れない。**
   縛る系は歩行を難しくして立ち往生を増やしうるので、同じランに混ぜると「対策が効かなかった」のか「縛りで歩けなくなった」のか区別できない。実機化は判定の後に別段階で。
3. **切り分けは「系統ごとに1つ抜く（leave-one-out）」で、B の変更を 3 系統に絞る。** 抜いても症状が出ないとき（冗長）は、逆に A に1つ足す実験で補う。小さい差は seed の揺れと区別できないので、**B は可能なら seed 2 本**。
4. **判定の物差しを先に固定する。** 学習時の地形・指令・報酬に依らない固定の評価（平地・固定指令・同じ env 数）で、全ランを同じ iter（1600）で比べる。判定基準は §3。

**「ダメだったら B を修正」の注意:** 失敗した全部入りを直し始めると交絡が積み上がる。**A を錨として残し、修正は1系統ずつ。**

## 1. 立ち止まりの給料（計算、2026-09-16）

`track_lin_vel_xy_exp` weight 1.0（std 0.5）＋ `track_ang_vel_z_exp` weight 0.5、20 s エピソード、立ったまま転ばない場合の1エピソード合計。heading 全周（立っていると yaw 指令は ±1 に張り付きがち）、standing env 2%。満点（完全追従）は 30。

| 指令レンジ | 立ち止まり | 満点比 |
|---|---|---|
| **08-21 既定（x ±1、y ±1）** | **7.2** | **0.24** |
| x ±1、y ±0.3 | 11.1 | 0.37 |
| x (−0.5, 1.0)、y ±0.3 | 12.9 | 0.43 |
| **x (−0.3, 0.6)、y ±0.3（`wrs_training_strategy.md` §4 の案）** | **16.4** | **0.55** |

**→ 戦略文書 §4 の「指令を絞る」案は、立ち止まりの給料を 2.3 倍にする。今夜は指令レンジを変えない。** 「速すぎる」対策で絞るなら、dense な足上げ報酬などで歩く側の取り分を増やしてから。

`track_lin_vel_xy_exp` の std を締めた場合（08-21 既定の指令）:

| std | 立ち止まり時の track_lin 期待値 | 横残差 0.1 m/s での値 | 横残差 0.2 m/s での値 |
|---|---|---|---|
| 0.50（既定） | 0.210 | 0.96 | 0.85 |
| **0.35** | **0.116** | **0.92** | **0.73** |
| 0.25 | 0.068 | 0.85 | 0.53 |

**既定の std 0.5 だと、横に 0.2 m/s 流れても報酬は 15% しか減らない＝カニ歩きがほぼ罰されない。** std を締めると「横流れの罰」と「立ち止まりの給料の削減」が同時に効く。0.25 は学習初期の信号が薄くなりすぎる恐れがあるので 0.35 を採用。

| A | B | 解釈 | 次 |
|---|---|---|---|
| 合格 | 合格 | base の修正で十分だった | カニ歩きの切り分けは不要。B の系統抜きは「歩行の質」の目的でだけ。段階1（実機化）へ |

## 4. 実験01の結果（2026-09-16、WRS機の報告 `REPORT_exp01_final.md` / `REPORT_ablation.md`）

- **問い1（base の前後修正だけで消えるか）→ 立ち往生は消えない。** カニ歩きは「歩いていないので測れない」。
- **問い2（直す系の複合）→ 消える。** B（2999）: S1 v_x 0.434、S2 0.903、S1・S2 の |v_y| ≤ 0.035、進行方向角 ≤ 9°、S5 v_y 0.290、全シナリオ転倒 0%。**歩いている方策では横流れは小さい＝base の前後の仮説と矛盾しない**（旧向きでの反実仮想ラン C16 は未実施なので因果の確定ではない）。
- **B の弱点:** 旋回が効かない（S6 指令 0.5 rad/s に実測 +0.028）。横移動・後退で heading が流れる（S5 +47°/10 s、S4 −19°）。滞空時間 0.07〜0.11 s と短く、**すり足の可能性**（録画未確認）。
- 4096 env の基準値: 1本 2.2 s/iter・8.1 GB、2本並走で合計 0.528 it/s（+17%）、3本で 0.556 it/s（+23%）。**並走はほとんど速くならない。** 温度は最高 62°C。

### 4-2. WRS側の読み（および指示書の前提）の訂正（Cowork 側で Isaac Lab v2.3.2 のソースを確認）

1. **`error_vel_xy` / `error_vel_yaw` はエピソード長に比例する。** `velocity_command.py` は毎ステップ `誤差 / (resampling_time_range[1] / step_dt)` を足し込み、エピソード終了時に記録する。20 s 完走で「平均誤差の2倍」。**正規化値 = 生値 × 500 / mean_episode_length**。
   - A: 500 → 2999 で 0.61 / 0.79 / 0.82 / 0.77 ＝**最初から歩いていない**（「500→1000 で局所解に落ちた」は誤読。立ったままの期待誤差 ≈0.75 と一致）。
   - B: 0.73 / 0.55 / **0.16** / **0.17**。error_vel_yaw は 0.26 → 0.38（「0.33→0.70」は長さの効果込み）。
   - **手順書 A5 と operator 指示書 §6 の「error_vel_xy 0.3 以下＝歩けている」はエピソード長を無視した目安だった。正規化値で読む**（手順書は次に触るとき直す）。
2. **`max_init_terrain_level` を上げると初期地形は難しくなる**（`None` で全レベルからランダム、`terrain_importer.py`）。**`random_uniform_terrain` は difficulty を無視する**ので、rough の 20% のタイルはレベル 0 でも `noise_range` の凹凸がそのまま出る。WRS側の「rough のまま max_init_terrain_level を上げる」案は**採らない**。「レベル 0 から上がらない」は「レベル 0 がすでに難しい」の意味。
3. **切り分けの結論「平地と報酬/std の組み合わせが要る」は iter 1000・seed 1 本だけ。** B も学習ログでは 1000 でまだ歩き始め。B 自身の seed 再現も無い（B2 はスループット基準で停止）。

### 4-3. 立ち止まりの給料の計算について

- 08-21 設定の立ち止まりは満点比 0.24 と低いのに、A は完全に立ち往生した。**「給料」だけでは説明できず、地形の難しさ・探索・足上げ報酬の形が効いている。**
- 旧 `feet_air_time`（threshold 0.2 s）は、B が実際に出した滞空時間 0.07〜0.11 s の歩幅では**毎歩マイナス**になる（A の Episode_Reward/feet_air_time は終始負）。この機体の自然な歩調では、旧報酬は「足を上げると罰」になっている疑い。
