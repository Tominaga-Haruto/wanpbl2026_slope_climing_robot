> **これは何:** 「動きが軽やかすぎる」問題を追ううちに、機体定義の数値が実機と合っていないと分かった。
> その裏どり結果と、Isaac Lab に入れる値の根拠をここにまとめる。数値の出どころを疑ったらここを見る。
>
> **⚠ 2026-09-14 に前提が2つ動いた。**
> ① **静止摩擦 0.54 → 0.30〜0.32 N·m**（旧値は Kt 経由の逆算で誤り）
> ② **Kt が未決になった。** 停止中 0.59 / 回転中 0.78 で一致せず、しかも 0.59 は
> 「ファームの内部定数を測っているだけ」の可能性がある（§2b）。**friction の根拠がここにぶら下がっている。**

## 0. AK80-9 の確定値

```python
AK80_FRICTION = 0.22        # 動摩擦 [N·m]      （2回測定: 0.2140 / 0.2249、差 5%）
AK80_ARMATURE = 9.77e-3     # 出力軸慣性 [kg·m²]（2回測定: 0.00979 / 0.00976、差 0.3%）
参考: 粘性摩擦 b ≈ 0.013 N·m/(rad/s)  （2回測定: 0.01510 / 0.01127、差 15%）
```

**慣性は 0.3% で一致した。文句なしの精度で、しかも電流を使わないので Kt に依存しない＝最も信頼できる。**

### friction: 0.54 は静止摩擦であって動摩擦ではなかった（さらに 0.54 自体が誤りだった）

| | 値 | 出どころ |
|---|---|---|
| 静止摩擦（動き出しに要る） | **0.30〜0.32 N·m** | **2026-09-14、MIT のトルクモードで実測**（0.30 で静止、0.32 で動き出し） |
| ~~静止摩擦（旧）~~ | ~~0.54 N·m~~ | 起動しきい値 0.63 A × **データシート Kt**。**Kt が違ったので誤り** |
| **動摩擦（動いている間）★これを使う** | **0.22 N·m** | ベンチ実測を2回（20〜120 deg/s の6点フィット） |

**Isaac Sim の `friction` は「動きに逆らうトルク」なので動摩擦が正しい。**

> **⚠ 動摩擦 0.22 も Kt 依存かもしれない（要確認・実機不要）。**
> 上の測定は「定常電流 0.259〜0.296 A」と並記されており、**0.22 ÷ 0.26 ≒ 0.85 ＝ 旧データシート Kt**
> にぴたりと一致してしまう。電流フィット由来なら Kt 0.59 で **0.15 N·m** に下がる
> （静止摩擦が 0.54 → 0.31 と約0.6倍になったのと同じ向き・同じ比率）。
> **`bench_inertia_friction.py` の `fric` が電流ベースか減速率ベースかをコードで確認すること。**

### armature: データシート由来の作り方が正しかった

```
実測 J     = 0.00977 kg·m²（2回平均）
データシート ×81 = 0.00906 kg·m²
比 = 1.08 倍   （減速機ぶんがあるので妥当。2回とも同じ比）
```
**ロータ慣性 × 減速比² という作り方が裏付けられた。** AK10-9 側も同じ作り方でよい見込み。

### 柱A への影響

15000 iter で「棒立ち」になった学習は friction 0.54 / 0.91 で回していた。**実際の抵抗は半分以下。**

| | friction | 不感帯（friction ÷ stiffness、stiffness 10〜15） |

## 0b. 実機で見つかった、シミュに無い挙動

### サーボモードの位置ループはリミットサイクルを起こす（C6・未決着）

0〜180度を45度刻みで保持したときの保持電流（無負荷・サーボモード）:

| 保持角度 | 保持電流 | 挙動 |
|---|---|---|
| 0度 | −0.05〜−0.08 A | ほぼゼロ。完全に安定 |
| 45度 | 0.81 → 0.43 A | 減衰して落ち着く |
| **90度** | 0.4 → 1.0 A を繰り返す | **15秒保持しても収束せず、約5Hz で振動し続けた** |
| 135度 | 0.44 → 0.63 A | 上昇して頭打ち |
| 180度 | 0.51 → 0.02 → 0.52 A | 下がってから上がる |

位置は ±0.05度 に収まっているので**軸はほとんど動いていない**が、**電流だけが往復し続ける。**

**最有力の解釈（未確定）:** 静止摩擦（**0.30〜0.32 N·m**）とサーボ内蔵の積分項が噛み合ったスティックスリップ。

**MIT での1点目（2026-09-14）:** Kp=2 / Kd=0.5 の保持で
**位置振れ幅 1.9 deg / 電流 平均 0.461 A・振れ幅 0.31 A・標準偏差 0.037。5Hz の振動は見えていない。**
ただし**MIT の位置原点が未確定のままの測定**なので参考値。原点を出してから `ramp` で決着させる。

**なぜ効いてくるか:** 10モーターが姿勢を保持するだけで**アイドル電流が数 A**／実機は常に微振動／
**MIT なら Kp/Kd を自分で決められ、積分項が無いので回避できる可能性。**

## 0c. ★ シムのゲイン ↔ 実機の MIT ゲイン（2026-09-14 新設）

MIT は1フレームに Kp / Kd / 位置 / 速度 / トルクを詰める。**シムの `stiffness`/`damping` が Kp/Kd に対応する**
というのが sim-to-real の要だが、**素通しではないことが分かった。**

| 項目 | 実測 | 含み |
|---|---|---|
| **実効 Kd = 指令 Kd × 0.48** | 0.25 / 0.5 / 1.0 の3点で一致 | **シムの damping 1.5 を出すには指令 3.1** |
| **実効 Kd の天井 = 2.4** | 指令の上限 5 × 0.48 | **シムの damping を 2.4 より上げると実機で再現できない** |
| **Kp のスケール** | **未測定** | Kd に係数があった以上、素通しと決めつけない |

**現行 damping 1.5 に対して余裕は 1.6 倍しかない。** §3b で「damping 項が支配的でトルクが恒常的に飽和」
と分かっているので、**damping を上げる方向の調整は実機で再現できない**という制約が新しく効いてくる。

### ゲインの量子化（12bit）

| 項目 | 1 LSB | 注意 |
|---|---|---|
| Kp | **0.1221** | **0.06 未満は 0 に潰れる。** 2026-09-14 に事故った |
| Kd | 0.00122 | 3.1 に対して 0.04%。問題なし |

## 2b. ★ Kt が未決になった（2026-09-14）

**データシート由来の Kt_out = 0.095 × 9 = 0.855 は実機と合わない。** ただし代わりの値も確定していない。

| 測り方 | 出た値 | 問題 |
|---|---|---|
| 停止中（指令トルク vs 電流、4点） | **0.59 N·m/A** | **循環の疑い。** モーターが「指令トルク ÷ 内部定数」で電流を決めているだけなら、これは**ファームの定数**であって物理 Kt ではない |
| 回転中（終端速度から逆算） | **0.78 N·m/A** | 摩擦の扱いが混入している可能性 |
| データシート | 0.855 | 実機と合わない |

`brk` の実測が循環を示唆している:
```
0.28 N*m 指令 → 電流 0.475 A   →  0.28/0.475 = 0.589
0.30 N*m 指令 → 電流 0.506 A   →  0.30/0.506 = 0.593
```
きれいに揃いすぎている。**指令値から電流が一意に決まっている、という形。**

**もし真の Kt が 0.78 なら、`t 0.30` で実際に出ているトルクは 0.40 N·m。** 静止摩擦も 0.42 になる。
**決着には分銲＋アームで外から測るしかない。** 3回試して3回とも分銲なしで無効だった。

**この1点に friction・effort_limit・`brk`/`sweep` の全部がぶら下がっている。**

## 3b. トルク実測と effort カリキュラム（2026-09-08）

> **⚠ この節の実測は「木構造が壊れた URDF」で取ったもの。**
> 2026-09-14 に CAD のインスタンス並び順を直したので、**再エクスポート後に取り直しになる。**
> **読み方（考え方）はそのまま有効。数値は使わない。**

### 何をしたか

2週間前の健全チェックポイント＋旧報酬設定を土台に、`AK80_EFFORT` を 30 → 22 → 18 → 12 → 9 と
4段階（各 800 iter）で下げる fine-tune を実施。

| 段階 | AK80_EFFORT | error_vel_xy | bad_orientation | terrain_levels | crab(符号付き/絶対値) |
|---|---|---|---|---|---|
| 開始 | 30 | 0.3〜0.4 | 低 | — | 0.061 / 0.146 |
| 1 | 22（AK80ピーク） | 0.25 | 0.2% | 0.56 | 0.044 / 0.217 |
| 2 | 18 | 0.29 | 0.5% | 0.86 | -0.002 / 0.268 |
| 3 | 12 | 0.31 | 0.2% | 0.89 | -0.090 / 0.221 |
| 4 | **9（AK80定格）** | 0.28 | 0.3% | 0.79 | 0.009 / **0.535** |

**4段階とも「歩けなくなる」ことはなかった。** ただし第4段で横方向の絶対値が 0.22 → 0.53 と2.4倍に増大。

### トルク要求（`computed_torque` の最大値）

| 関節 | 機種 | 定格 / ピーク | 実測要求 |
|---|---|---|---|
| HFE | AK80-9 | 9 / 22 | **43.55〜48 N·m** |
| KFE | AK10-9 | 18 / 53 | **60 N·m** |
| FFE | AK80-9 | 9 / 22 | **41 N·m** |
| HR | AK10-9 | 18 / 53 | 18.66 N·m |

### ★ この数字の正しい読み方（重要）

**`computed_torque` は「物理的に必要なトルク」ではない。PD 制御器が要求した値である。**

```
computed_torque = stiffness × (目標角 − 現在角) + damping × 関節速度
                = 15 × 位置誤差            + 1.5 × 関節速度
```

**43 N·m を位置誤差だけで説明するには 2.9 rad（166度）の誤差が要る。ありえない。**
つまり**damping 項（1.5 × 関節速度）が支配している。** 関節速度 25 rad/s で 37.5 N·m に達する。

**→ この数字が言っているのは「モーターが小さい」ではなく「脚の振りが速すぎる」。**
**歩容を遅くすれば要求トルクは大きく下がる。**

### ★ 「9 N·m でも歩けた」の含意

**恒常的に飽和したまま歩いている**（第2段で p95 が上限に張り付き始めた）。これは:

- PD が線形域で動いていない＝**stiffness / damping が実質的に意味を持っていない**
- **sim2real の前提が崩れる。** MIT の利点は「シムの stiffness/damping = 実機の Kp/Kd」だが、
  飽和中はその対応が成立しない。**§0c の「実効 Kd の天井 2.4」と合わせて、damping 側に余地が少ない**
- 定格 9 N·m に張り付く＝**熱的に余裕ゼロ。** 坂はさらにトルクを要求する

### ★ モデルの穴: トルク-速度特性が入っていない

`DelayedPDActuatorCfg` の `effort_limit` は**関節速度に依らずフラット。**
実機の BLDC は速度が上がると逆起電力で出せるトルクが落ちる（droop）。

→ `DCMotorCfg` 系（`saturation_effort` + `velocity_limit` で droop を表現）への移行を検討する。
**実機の C3（無負荷最大速度）を測れば droop を実測値で入れられる。**
```
source ~/projects/slope-climbing-robot/isaac_env/bin/activate && python -c \"import isaaclab.actuators as a; print([n for n in dir(a) if 'Cfg' in n])\"
```

### 測定上の交絡（次回は潰すこと）

1. **段ごとに terrain_levels が違う（0.56 → 0.89 → 0.79）。** 横ぶれ増大が effort のせいか地形のせいか分離できていない。
2. **crab が残差（v_y − cmd_y）か生の v_y か要確認。**
3. **第3段の「偏り」（符号付き -0.090）は 2σ 程度でノイズの可能性。**

### 未検証の相互作用

**AK80 カリキュラム中、KFE / HAA / HR は `AK10_EFFORT` のまま余裕があった。**
HFE を絞った分の仕事を KFE に逃がして帳尻を合わせている可能性がある。
**→ AK10 側も実機値に絞ると、今「合格」している結果が崩れる可能性が高い。**

## 4. 値の作り方

**armature** = ロータ慣性 × 減速比²（coast の実測値があるならそちらを優先）
```
AK10-9: 1.002e-4  × 81 = 8.116e-3 kg·m²   （未実測）
AK80-9: 1.1183e-4 × 81 = 9.058e-3 kg·m²   → ★実測 9.77e-3 を使う
```

**friction（Isaac Sim 5.0 以降は「トルク [N·m]」）**
```
AK80-9: ★ベンチ実測 0.22 N·m（動摩擦、2回測定）※Kt 依存の疑いあり（§0）
AK10-9: 未実測。暫定 0.37（外挿）
```

**粘性摩擦 b ≈ 0.013:** `friction` は速度に依らない一定トルクなので表現できない。
`damping` は PD の D ゲインであって粘性摩擦とは別物なので**混ぜてはいけない。**

**effort_limit** = 定格トルク。方策は連続で動き続けるので、短時間しか出せないピーク基準では実機で再現できない。

## 5. Isaac Lab 側の仕様メモ（公式ソースで確認）

- `armature`: 「対応する関節空間の慣性に直接加算される」。単位は関節側の kg·m²。
- `friction`: 「4.5 では係数、5.0 以降はトルク」。**本環境は Isaac Sim 5.1 → トルク。**
- `effort_limit` は explicit アクチュエータで効く。本機は `DelayedPDActuatorCfg`（explicit）なので**そのまま効く**。
- **`velocity_limit` は DCMotor 系でのみ使われる。`DelayedPD` では実質効かない可能性（要確認）。**

出典: [actuator_base_cfg.py](https://github.com/isaac-sim/IsaacLab/blob/main/source/isaaclab/isaaclab/actuators/actuator_base_cfg.py)
