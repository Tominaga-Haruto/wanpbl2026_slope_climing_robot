# M5: 実機の原点姿勢と H の関節角を対応付ける

## 目的

実機の各 CAN ID の角度を、H_eff13p5@2999 が使う10関節の角度へ変換できるようにする。これは歩かせる試験ではない。完了物は、10関節の対応表と、毎回同じ原点を作る物理手順である。

H の順番は `LL_HR, LR_HR, LL_HAA, LR_HAA, LL_HFE, LR_HFE, LL_KFE, LR_KFE, LL_FFE, LR_FFE`。座標と既定姿勢の正本は `reference/robot_model_conventions.md`、ONNX側の契約は成果物の `obs_contract.md` である。

## `o 0` の意味と限界

- `o 0` はモード5の原点設定フレームを送り、その時点のモーター角をサーボ／MIT座標のゼロにする。**軸を動かす命令ではない。**
- 次に通電したままMIT位置指令を出す場合、目標角はこのゼロからの相対角になる。従って、Hのゼロ姿勢で `o 0` を打てば、Hの初期角は `(-0.1745, +0.3491, -0.1745)` 等の相対目標として表せる。
- ID34での `ocheck` は「`o 0`でMIT原点も動く」と確認済みだが、**全10台・電源断後も同じ原点が残ることは未確認**である。電源を切った後は原点が有効と仮定せず、同じ物理基準姿勢で再設定・確認する。
- `o 0`直後はコンソール内の原点検証状態が未検証に戻る。`morg`／`overify`が済んでいない個体に位置系の実験を続けない。今回のM5では `hold`、`step`、`jog`、方策送信をしない。

## 実機が必要か

**必要。** ただし必要なのは各関節を動かすことではなく、実物を同じ基準姿勢に置き、各CAN IDで `o 0` とフィードバックを記録することである。

## 前提・停止条件

- ロボット全体を、脚が落下・回転しないように吊るか機械的に支持する。治具が無いなら、手で支えるだけの状態では開始しない。
- 非常時に切る主電源を手元に置く。姿勢を作る／配線に触るときは主電源を切る。
- ID・機種・関節名・実機正方向は、ユーザー確定済みの表を使う。1件でも表に無いIDを推測で使わない。
- 固定治具が無い現状では「再現可能な物理基準姿勢」をまだ保証できない。今日は表の雛形、支持方法、写真、寸法の記録までを完了とし、`o 0`の一括設定は基準姿勢を再現できると判断できた場合だけ行う。

## 今日の手順

### 1. 基準姿勢を決め、記録する（通電なし）

1. ロボットを支持し、全関節0のゼロ姿勢（脚がほぼ真下、爪先はbaseの+X、足裏はほぼ水平）を作る。
2. 正面・右側・左側・上面の写真を撮る。各脚について、HAAが0、足裏が水平であることを目視する。
3. 再現に使う支持点、定規で読む寸法、部品との位置関係を記録する。写真だけで次回同じ姿勢に戻せないなら、ここで停止する。

### 2. 変換表を作る（通電なし）

`instructions/deployment_04_joint_mapping_instruction.md` の形式で、各10関節について次を埋める。

| H順 | 関節名 | CAN ID（10進） | 機種 | 実機正方向→H正方向の符号 | 基準姿勢でのMIT角 | H角 |
|---|---|---:|---|---:|---:|---:|

H角はゼロ姿勢なら全て0。歩行開始時のH既定角は、HR/HAA=0、HFE/FFE=-0.1745 rad、KFE=+0.3491 radである。

### 3. `o 0` を記録する（基準姿勢を再現できる場合だけ）

ノートPCの `C:\Users\harut\Connect2USB2CAN` で `py -3.13 motor_console_ver8.py` を起動する。1台ずつ、IDと機種をプロンプト表示で照合し、フィードバックが来ていることを `s` で確認してから `o 0` を送る。`o 0`の直後にも `s` を実行し、CSVと画面記録へ残す。

この段階で軸を動かすコマンドは使わない。err≠0、フィードバック途絶、支持のずれ、想定外の動きがあれば、主電源を切り、そこで終了する。

### 4. 完了判定

次の4点がそろったらM5は完了である。

1. H順10件のID・機種・符号が表にある。
2. 各関節を同じ物理基準姿勢へ戻す方法が写真・寸法つきである。
3. 基準姿勢でのMIT角とH角の変換式が書かれている。
4. 電源断後は原点を再確認／再設定する運用が表に明記されている。
