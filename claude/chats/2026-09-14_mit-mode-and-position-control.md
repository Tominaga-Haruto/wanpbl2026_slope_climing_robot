## 決めたこと・分かったこと

### MIT はモード8だった（旧 A8「MITには入れない」を撤回）

| 項目 | 確定内容 |
|---|---|
| 送信CAN ID | `(8 << 8) \\| モーターID` の拡張29bit。ID34 → `0x822` |
| ペイロード順 | **Kp → Kd → 位置 → 速度 → トルク**（マニュアル44-45頁） |
| enable | **不要** |
| 応答 | **MIT専用応答は無い。** サーボ形式 `0x29xx` の 50Hz 定期が流れ続ける |
| レンジ | AK80-9: 位置±12.56 rad / 速度±65 / トルク±18。AK10-9: 速度±28 / トルク±54 |

**MIT は独立した別プロトコルではなく、サーボのモード0〜6と同じ枠組みのモード違いだった。**

**2026-09-07 に `ext`（0x82B）を送ってバスが落ちた件の真因も判明した。**
宛先は正しかった。**classic MIT 並び（位置が先頭）で「位置0rad」を送ると、オフセットバイナリの `0x7FFF` が
先頭2バイトに来て、Kp=250 / Kd=4.84 と読まれ 48.7 A が流れていた。**
当時「ACK が返っていない」と解釈した12件の再送も、この過電流保護の副作用で説明がつく。
**→「ext 方式は使うな」という旧ルールは無効。**

**副次的な利点:** Kp/Kd が先頭にあるので、**Kp=Kd=0 なら位置・速度の欄が何であっても無視される。**
＝零指令が本当に無害。classic MIT にはこの性質が無い。

### ゲインの量子化（この日いちばん高くついた発見）

12bit なので Kp の 1LSB = 500/4095 = **0.1221**。

```
Kp 指令 0.05 → 整数 0 → 実際に送られる 0.0000   ★
Kp 指令 0.10 → 整数 0 → 実際に送られる 0.0000   ★
Kp 指令 0.25 → 整数 2 → 実際に送られる 0.2442
```

**`morg` を Kp=0.05 で走らせたので、全行程 Kp=0 で電流はノイズだけ**（R²=0.001）。
そこから出た offset は「ほぼ0 ÷ ほぼ0」のゴミだった。**エラーは一切出ない種類の失敗。**

### 実効 Kd = 指令 Kd × 0.48

- シムの damping 1.5 を出すには **指令 Kd ≈ 3.1**
- 指令の上限が 5 なので **実効 Kd の天井は 2.4**
- → **シムの damping を 2.4 より上げると実機で再現できない。** 現行 1.5 に対して余裕は 1.6 倍だけ
- **Kp のスケールは未測定。** Kd に係数があった以上、素通しと決めつけない

### 静止摩擦 0.30〜0.32 N·m（旧 0.54 は誤り）

`brk` を MIT のトルクモードで回して再現。0.30 で静止、0.32 で動き出し。
旧 0.54 は「起動しきい値 0.63 A × データシート Kt」で逆算した値で、**Kt が違ったので連動して誤っていた。**

### ★ Kt が未決になった（循環の疑い）

```
0.28 N*m 指令 → 電流 0.475 A  →  0.589
0.30 N*m 指令 → 電流 0.506 A  →  0.593
```

きれいに 0.59 が出るが、**これは「モーターが指令トルク ÷ 内部定数で電流を決めている」だけかもしれない。**
だとすると 0.59 は**ファームの定数**であって物理 Kt ではない。
**停止中 0.59 / 回転中 0.78 の食い違いは、これで説明がつく。**

もし真の Kt が 0.78 なら、`t 0.30` で実際に出ているトルクは **0.40 N·m**、静止摩擦も 0.42 になる。
**friction・effort_limit・`brk`/`sweep` の数字が全部ここにぶら下がっている。分銲＋アームで外から測るしかない。**

### 動摩擦 0.22 も Kt 依存かもしれない（新規の疑い）

`actuator_params.md` には「2回測定 0.2140 / 0.2249」と並んで「定常電流 0.259〜0.296 A」とある。
**0.22 ÷ 0.26 ≒ 0.85 ＝ 旧データシート Kt** にぴたりと一致してしまう。
電流フィット由来なら Kt 0.59 で **0.15 N·m** に下がる（静止摩擦が 0.6倍になったのと同じ比率）。
**`bench_inertia_friction.py` の `fric` が電流ベースか減速率ベースかをコードで見れば決まる。実機不要。**

### 位置制御は一度も成功していない（現在の壁）

**MIT の位置原点はサーボの原点と別物。** その差がまるごと偏差になる。

| やったこと | 結果 |
|---|---|
| サーボ角をそのまま MIT の目標位置に（Kp=2） | 16.5 A |
| 同じ条件で 90度ステップ（Kp=5） | **39.7 A**（Bus Current Limit 35A 超） |
| ゴミ原点のまま `hold 1 0 2`（**Kd=0**） | **277 deg/s の暴走** |

## 手を動かした場所

### 発見したバグ

**`require_mit_position()` が「`s` に `[MIT]` と表示されるまで Kp>0 を禁止」という条件だった。**
ところが **MIT 専用の応答フレームは存在しない**（サーボ形式が流れ続ける）ので、
**この条件は永久に満たされない＝ hold / ramp / step / m8 が一生使えない状態だった。**

### `motor_console_ver6.py` への変更（`.bak_morg` / `.bak_morg2` あり）

1. **`morg` コマンドを新規実装。**
   ```
   I = (Kp_eff / Kt) × ((X − θ_servo) − offset)
   ```
   目標位置 X を5点振って電流を直線で当て、**ゼロ交差を外挿**する。
   **ゼロ交差は傾きに依存しないので、Kt も Kp のスケールも未知のまま offset が求まる。**
   サンプルごとに θ_servo を読んで差を取るので、軸が多少動いても効かない。
   2回目以降は前回の推定値を中心に振る＝外挿でなく内挿になり精度が上がる
   （合成データで検算: 1回目は誤差 6.6 deg、2回目で収束）。
2. **ゲートの条件を「`[MIT]` 表示」から「`morg` で原点を実測済み」に変更。**
3. **当てはまりが悪ければ原点を採用しない**（R² < 0.70 または傾き < 0.02 A/rad）。
   **ゴミ原点で `hold` を許したのが 277 deg/s の直接原因だったので、ここが一番効く安全弁。**
4. **Kp>0 で Kd=0 を禁止。**
5. **実際に送られる Kp/Kd を毎回表示**（量子化の可視化）。
6. **`log on`** でセッションの画面内容をファイルに残せるようにした。
7. `MORG_KP` を 0.05 → **0.25** に（量子化対策）、Kd=0.5 を併用、200 ERPM 超のサンプルは捨てる。

**ファイルは CRLF なので、パッチ後に改行コードを揃え直した**（一度 91 個の裸 LF が混入した）。

### 実機で取れたデータ

- `t 0 2` → 零トルクで電流ノイズのみ（±0.05 A）＝零指令が無害であることの確認
- `brk` → **静止摩擦 0.30〜0.32 N·m**。0.28 で 0.475 A、0.30 で 0.506 A
- `ramp` 1段目（Kp=2 / Kd=0.5）→ 位置振れ幅 1.9 deg、電流 平均 0.461 A・振れ幅 0.31 A・標準偏差 0.037
  **5Hz のリミットサイクルは見えていない**が、原点がゴミのままの測定なので参考値
- セッション記録: `bench_20260914_session1.txt`、`bench_20260914_185044.txt`

### 事故と復旧

`brk` で 0.32 N·m に達した瞬間、無負荷なので 8580 ERPM（272 deg/s）まで加速 → 速度超過で中断。
**このとき走っていたのは修正前のコンソールで、速度超過が「電源入れ直しが必要」な落ち方だった。**
アダプタが bus-off になり、**スクリプトの再起動だけでは戻らなかった**
（`health` が「送信0件・受信0件・エコー150件」）。
**電源OFF → USB2CAN 抜き差し → 電源ON で復旧。**
現行版は同じ状況で零トルクを送って自力で止まる。
