# 2026-09-20 旋回実験の提案

## 目的

`H_eff13p5@2999` を土台に、平地の通常速度追従を残したまま、その場旋回を十分な頻度で
経験させる。実機候補を置き換える実験ではない。

## 採用する1本

既存の `TurnAwareVelocityCommand` を用いる。純旋回を 35% にして、残りには通常の
速度指令と translate-only 指令を残す。純旋回では `(vx, vy)=(0,0)`、
`wz=+-U(0.3,1.0)` であり、heading と standing の再上書きは受けない。

- `rel_turn_in_place_envs=0.35`（既存の 0.20 から増加）
- `rel_translate_only_envs=0.15`
- `rel_heading_envs=0.5`、standing 比率 0.02
- yaw 追従報酬は `std=0.35`、weight 1.0
- 両方の足上げ項で `yaw_gate=true`。純旋回でも脚を上げる利得をゼロにしない。
- H@2999 から追加 15000 iter。`--max_iterations` は resume 元からの追加回数。

これは過去の `L_angstd_w1` の一時的な成功を再検証しつつ、失敗した理由の一つである
純旋回の出現不足を直接変える実験である。N_w1_seed2 と N_w1p5 は連続300 iterの
合格範囲を再現できなかったため、結果は checkpoint ごとに評価する。

## 速度方向へ機首を向ける報酬案（今回は入れない）

これは pure yaw tracking とは別の目的で、`vy` を許す現在の操作意味と衝突する。
必要なら、world frame の目標移動ベクトルを command に持たせ、`atan2(v_goal_y,
v_goal_x)` を目標 heading として、並進速度が 0.2 m/s を超える場合だけ
`exp(-(wrap(yaw-yaw_goal)/0.5)^2)` を加点する。body-frame の `(vx,vy)` だけから
同じ報酬を作ると、横移動（前を向いたまま右へ）を罰するため、現行のコントローラー
仕様では別モードにすべきである。

## 判定

S6/S9 を 256 env・評価 seed 2回で測る。各保存点で、符号一致、`|wz| >= 0.25`、
左右比 0.5--2、`|(vx,vy)| <= 0.10`、転倒 5% 以下、両足の足上げを満たすこと。
さらに S1--S8 の通常基準とトルクを落とさず、連続300 iter以上を合格範囲とする。
