# 2026-09-23 D10-2 の結果分析と D10-3 の実装

## 依頼

D10-2（`procedures/d10_2_吊り全身MITから床上_実験手順.md`）を実施した結果を分析し、次の実験のために実装し、実験手順書も整える。このチャットは1回きりで次へ引き継ぐので指示書も作る。あわせて D7 起動時の `USB open失敗 → 再試行` は大丈夫かという質問。

本人の所見: 完全に吊って脚を手で優しく支えた。R3 からは紐で少し吊って床に立たせた。R1 の前と R3 の前にゼロ点合わせ。R1 は初期姿勢を正そうと動いた気がする、速度はゼロだった。R2 は左右の足が前後に動いた気がする。R3・R4 はあまり動いた感じがしなかった。

## やったこと

1. `logs\d10_2_r*.csv` 5本を読み、**全本が `ramp` 段階のみ・policy 行ゼロ**であることを確認（6.61 / 2.33 / 1.94 / 1.77 / 1.41 秒）。CSV が `finally` で書かれる実装なので、部分行＝例外で抜けたということ。
2. `logs\d7_origin\session_*.txt` と CSV の mtime で時系列を復元。R3 が走っていないこと、ver3 が同名で2回走り1回目が消えたことを特定。
3. ユーザーに画面ログを請求。**全5本が `motion/current abort`（1.01〜1.05 A、速度は全て +0.0 deg/s）**、止めた軸は 0x11 LL_HAA / 0x21 LL_HFE / 0x2A LR_HFE / 0x22 LR_FFE と判明。
4. URDF（総質量 10.106 kg）から各軸の静的自重トルクを計算し、`c_p` で電流に換算。**HAA はゼロ姿勢で 1.70 A、HFE は最悪 7.36 A を要する。中止は 1.0 A。** AK80-9 の HFE は Kp 28.68 A/rad なので 2.0° の追従遅れで中止に達する。**D10-2 は成立し得なかった。**
5. `Initial policy targets` と D7 の `oa` 事前表示から、**原点が毎回ちがう姿勢で宣言されている**ことを発見（宣言のたびにゼロが 20〜30° 動く）。
6. 送信器を実装（build `D10_3_AXISLOG_20260923_1200`）: 全軸CSV記録、`AXIS SNAPSHOT`、多軸 `--analyze` と `INCOMPLETE` 表示、軸ごとの電流中止（**既定は 1.0 A のまま**）、`--gravity-limits`（要承認）、`--hold-pose` 新モード。テスト 58→73本。
7. `d7_origin_console.py` と `DualBus.open` の `OPEN_ATTEMPTS` を 2→3。
8. 文書: `reports/2026-09-23_d10-2_result.md`、`procedures/d10_3_吊り保持測定_実験手順.md`、`handoffs/2026-09-23_d10-3_吊り保持測定.md`、`CONTEXT.md` 更新、旧 handoff / 旧 procedure の冒頭に置き換え行。

## 結論

- **D10-2 の判定表 1〜8 はどれにも当たらない。** 全本が ramp 中の `current abort`。本人の所見はすべてこの1つの事実の見え方の違いだった。
- **1.0 A は D9 の1軸 probe 用の値で、自重を支える run に持ち込んだのが誤り。** 方策が使ってよい量の 2.4〜3.9%。
- 次は方策を回さず `--hold-pose` で軸ごとの保持電流を実測し、**その表から**床上の中止値を決める。推定で決めない。
