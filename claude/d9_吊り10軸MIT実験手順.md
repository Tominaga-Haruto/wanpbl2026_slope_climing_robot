# D9: 吊り支持・10軸MIT送信 実験手順

> D8の `C:\Users\harut\Connect2USB2CAN\ver9_d8_sender.py` は完成済みである。この手順ではコードを編集しない。異音・接触・支持ずれ・errのいずれかで、PC操作より先に主電源を切る。

## 0. この実験で起きること

`--arm` を付けると、T265とUSB2CANの両chを開き、10軸の受信IDからこのプロセスの送信経路を確定してから50 HzでMIT位置指令を送る。最初は速度指令ゼロ・最大5秒である。経路確定前はMITを送らない。終了・例外時には、経路確定済みの全軸へKp=Kd=位置=速度=トルク=0のMITフレームを3回送る。電源遮断の代わりにはならない。

## 1. 開始条件

- [ ] 床から完全に離れ、棒または治具で自立支持されている。
- [ ] 電源遮断担当が主電源に手を置ける。
- [ ] D7後に姿勢・配線・部品を変えていない。変えたならD7を先にやり直す。
- [ ] 既決の機械ゼロ姿勢でD7の`o`を全10軸へ行い、設定後の0°付近を確認した**同一通電中**である。AK80-9 V3.0はシングルエンコーダのため、電源断後の恒久原点を前提にしない。
- [ ] `d9_仮_吊りCAN統合_実験手順.md` の受信確認が10/10、err=0で合格済み。
- [ ] T265、**1台でch=0/ch=1を公開するUSB2CAN V3.3 1台**、全モーター電源が接続済み。D7でこの構成の10軸が一意に受信済みであること。ch=0/1の左右固定は要求しない。

一つでも満たさなければ実行しない。

> **D9停止点（2026-09-21）:** T265の `No device connected` は修正済みで、初回MIT実行は制御ループまで到達した。しかし `0x2A`（**LR_HFE**）のフィードバックが0.30秒を超えて途絶し、`stale feedback 0x2A` で中止した。`--vx 0 --vy 0 --wz 0` は方策への速度要求がゼロであってMIT位置目標はゼロではないため、意図しない移動がない確認にはならない。T265とUSB2CANの同時接続ではreset失敗がランダムに起こり、成功後のUSB ch=0/1列挙も固定しない。全身10軸の本節3は再実行しない。次は `d9_受信確認_実行シート.md` だけを使い、送信なしで10/10軸（特に0x2A）の `err=0` と `age <= 0.3 s` を確認する。

## 3. 送信する最初の1回

1. 主電源をONにする。手を離して支持が安定していることを確認する。
2. 数秒待つ。D7受信確認と同じく、10軸の定期フィードバックが来るまで送信しない。
3. PowerShellで次の**1行だけ**を実行する。

```powershell
.venv310\Scripts\python.exe ver9_d8_sender.py --arm --package C:\Users\harut\wanpbl2026_slope_climing_robot\H_eff13p5_2999\H_eff13p5_2999 --duration 2 --csv logs\d9_zero_01.csv --vx 0 --vy 0 --wz 0
```

この最初の実行はゼロ速度指令で2秒だけである。脚が大きく動く、異音、支持ずれ、電流・速度異常、例外表示のどれかで主電源をOFFにする。
